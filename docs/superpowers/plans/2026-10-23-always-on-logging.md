## 3. Design (TIER 1 unless marked)

### 3.1 One logger, one routing decision, two types (finding 5)

- **`:core:model`, package `com.rokid.context.core.log`, pure Kotlin.** `enum Level {D,I,W,E}`. Two interfaces with different roles, so that nothing can bypass the gate:
  - `fun interface LogPort { fun log(level, tag, msg) }` is the CALL-SIDE type. Everything that logs (production code, `:core:*`, 3b) holds a `LogPort`. `object PcLog : LogPort` is the process default; `PcLog.port(area): LogPort` returns an adapter that calls `PcLog` (so it is gated by construction). **3b's `CanvasLogSink` is `typealias CanvasLogSink = LogPort`, bound to `PcLog.port("canvas")`; no one injects a concrete sink.**
  - `interface LogSink { fun emit(line: Line, route: Route) }` is the BACKEND SPI, implemented only by `GlassesLogSink` and `PhoneLogSink`, installed once by `PcLog.install(sink, policy)`, and receives only lines the central policy already routed. A sink never decides; it executes `route`.
- **One central routing function in one file `LogPolicy.kt`:** `fun route(level: Level, tag: String, diag: Boolean): Route` returning `Route(logcat: Boolean, file: Boolean)`; `PcLog` is the only caller. Table (the resolved contradiction): **logcat** = `level >= I || diag` (today's behaviour: I/W/E always visible to `LogReader`, D only when diagnostics are on); **diagnostic file** = `diag || level >= W` (warnings and errors are kept even with diagnostics off, because a failure with no record is exactly the defect being fixed; I and D go to the file only while diagnostics are on). `diag` = `diagnosticEnabled()` installed with the sink (phone: `DeveloperModeStore.enabled`; glasses: the persisted `diag_record`, 3.4). Changing when or what to log later is a one-function edit. Default for the glasses file I-lines with diagnostics off: dropped (today they are written; this reduces retention and is called out in Q8).
- **Tests of the single gate (RED first):** one matrix `level x diag` asserts the same `Route` through (a) `PcLog.d/i/w/e` directly and (b) `PcLog.port("canvas")` and any `LogPort` handed to 3b; a test proves no public API accepts a `LogSink` as a call target; a throwing sink or policy never throws into the caller (non-throwing contract).
- Before `install` (and in host unit tests) lines go to a bounded ring buffer, so JVM-only modules and tests need no Android. Call shape equals `android.util.Log` (`d/i/w/e(tag,msg)`, `w(tag,msg,Throwable)`): migration is `Log.` to `PcLog.` plus an import swap; a Throwable logs only its class name.

### 3.2 Bounded async writer (finding 7), `:core:model` `AsyncLineWriter` (pure JVM, shared by both sinks)

`append(line)` is a non-blocking `offer` on a bounded queue (default 2048 lines); on overflow it drops the oldest, counts `dropped`, and the writer emits one `log overflow dropped=<n>` line when it catches up. One daemon thread does formatting, rotation (existing `DiagFile.append` logic moved, not rewritten: glasses 2 x 1.5 MB, phone 2 x 3 MB) and file IO; every IO failure is caught, counted (`ioFailures`) and never propagated; the thread backs off after repeated failure. **Fencing:** `fence()` bumps a generation; queued and in-flight lines carrying an older generation are discarded, and `clear()` deletes both rotations on the writer thread (used by Delete all, section 3.9, and the QnA file, section 5). **Never blocks callers:** no lock shared with callers is held across IO; recorder, sensor, session and gate locks never wait for the logger (the logger takes no lock the recorder takes; the recorder only calls `PcLog` after releasing locks it holds across a batch, enforced by a test that logs from inside a held fake recorder lock with the writer stalled). Tests: `StalledWriterDoesNotBlockCallers` (writer blocked on a latch, 100k lines return promptly, queue size stays <= capacity, `dropped` counted), `WriterIoFailureIsolated`, `FenceDropsQueuedLines`, `RotationKeepsTwoFiles`.

### 3.3 Privacy: call-site audit, not a heuristic (finding 6)

The old URL/base64 "rejection" is dropped as a privacy claim. Rules, enforced by an audit table per migrated module (WP deliverable, reviewed by Codex) and by tests:
- A message is a constant template plus dynamic fields drawn only from: integer counts and durations, booleans, enum names, a bounded classification string from a closed list, `Throwable.javaClass.simpleName`, sizes in bytes/MB. **Forbidden dynamic fields:** user-configurable names (endpoint, role, model names), file paths and file names, frame/photo/job/ask/trace ids, URLs, hosts, tokens and codes, question or answer text, provider error bodies, `Throwable.message`. Known offenders to fix by rewrite, not by wrapping: `RoleRunner.kt:100` (`reply.endpoint.name`, verified), `RokidFrameInbox.kt` (`inbox.absolutePath`, `file.absolutePath`, `frameId`, lines 121/283/316/319, verified), `CaptureService` DiagLog lines carrying frame ids, any `$e.message`-style provider text.
- Helpers `LogFields.count(n)`, `LogFields.cls(t)`, `LogFields.enum(e)` make the allowed shapes the easy path. `SafeLog` stays and is reused.
- The sink applies a last-resort scrubber (long digit/hex/base64 runs and `scheme://` become `<redacted>`) as defense in depth only; it never throws, never rejects, and nothing relies on it.
- Tests: a host test table (`PrivacyAuditTest`) feeds ordinary configured names ("My Home Server"), an id-shaped string, a path and a provider error sentence through each audited call-site template and asserts none reaches the sink; a fixture test proves the scrubber is non-throwing and non-claiming.
Glasses audit is part of LGC3; every tier 2 migration WP carries its module's audit table and its own privacy tests.

### 3.4 The persisted glasses flag, epoch bootstrap, coherent contract (finding 8)

- **Wire (additive, PROTOCOL_VERSION stays 1):** `HudSettings.diagRecord: Boolean = false`. Not in `TraceSettingsHash`, not in the plan config hash. New glasses-to-phone status (section 3.7) reports the flag state and whether the epoch is saved.
- **Three glasses states, persisted in one `AtomicFile` `files/diag_state` (flag requested, epoch saved, last applied deletion counter), never inferred from "ever linked":**
  - `UNPROVISIONED`: never contacted by a phone, flag false, no epoch. Records nothing; this is the expected default of an unpaired glasses, reported as `unprovisioned`, not as a fault.
  - `ARMED_NO_EPOCH`: `diagRecord=true` was received but no valid epoch is durably saved. The flag is stored as `requested`, `diagnosticEnabled()` and `diagEnabled()` stay false for the TRACE gate, the state line says `armed_no_epoch`, and the status field tells the phone.
  - `ENABLED`: flag requested AND epoch durably saved. Order of application on glasses, always: (1) apply deletion fences/epoch wipe from the arriving `TraceControl` (3.9), (2) durably save the epoch, (3) only then does `requested` become effective. Settings arriving first just record `requested`; control arriving later completes it; either order, and a restart between them, converges.
- **Phone side coherence (LGC4P):** at every session-ready the phone sends the `HudSettings` and then the `TraceControl` (epoch, fences, cleanup) as today, and **keeps re-sending the control (bounded backoff, 5 s to 60 s) while the glasses status shows `armed_no_epoch` or an unacknowledged cleanup**, until the status shows `ENABLED` or the flag is off. Retained: strict phone import validation (`TraceImport` `other_install` unchanged); Q3 default stays "no epoch, no recording", but it is now visible and self-healing instead of silent.
- Developer mode turned off: the phone sets `diagRecord=false` (republished on change); glasses state goes `requested=false`, the running diagnostic trace closes `stop`, nothing is deleted. Residual risk R2 (switched off while unlinked) unchanged and shown in the status.
- **Tests (RED first):** `SettingsBeforeControlBecomesEnabledAfterEpochSaved`, `ControlBeforeSettings`, `InterruptionBetweenSettingsAndControlThenOfflineRestartStillArmedNotLostNotEnabled`, `UnprovisionedGlassesReportsUnprovisionedNotFault`, `DeletionFenceAppliedBeforeEpochSaved`, `OldPhoneSettingsDefaultOff`, `WireDiagRecordRoundTrip`, `PhoneRetriesControlUntilStatusEnabled`. Mutation: make `requested` effective before the epoch is saved: `SettingsBeforeControl...` fails.

### 3.5 The trace gate (glasses `TraceRecorder`)

`collectingNow(now) = collect && now < collectUntil` becomes `diagEnabled() || collectWindow(now)` (`diagEnabled: () -> Boolean`, default `{ false }`, so existing tests stay green), used in `wantsStart`, `start`, `onControl` (window expiry closes only window-driven traces; a diagnostic trace does not close because a collect window ended) and `after`. The laptop `pc_trace_ctl` collect window keeps its own `collectUntil`. A clean-boundary start keeps the existing rules (QUIET, no camera episode, empty gate window, capture unblocked), the initial `cx rs pf gp pl` events and the 10 s pre-roll. **Per-session sealing:** the trace closes `stop` when the capture session stops (including heat STOP/pause) and the next session opens a new one at its first clean boundary; existing closes (`pause`, `plan`, `plan_revert`, `settings`, `cap`) apply; a killed process leaves `imu_trace_tmp/<id>` that `recover()` seals PARTIAL on the io thread, and recording starts only after `recovered`. Per-trace cap `MAX_TRACE_RAW_BYTES` 256 MiB: a full trace closes `cap` and the next starts at the next boundary. The recorder never references pairing or `canTransfer()` (grep test).

### 3.6 Instrumentation with real data sources (finding 13)

### 3.7 Space policy: never stop recording except physical exhaustion (finding 9)

Replace "at `diskCapBytes` no new trace starts" at EVERY place the limit acts today: `wantsStart`, `start`, `writeBatch`, and recovery's `seal`. Definitions: **soft budget** = min(1.5 GB, 20 % of `StatFs` free space measured at start and re-measured each trace start) (Q4); **free-space floor** = 64 MB of physical free space; **`needBytes`** = the next batch size at `writeBatch`, the 256 MiB per-trace raw cap headroom (or 32 MiB minimum) at `start`, and the sealing reserve at `seal`; **sealing reserve** = 16 MB always kept for manifest/seal (never spent by the soft budget). `TraceStorage.reclaim(needBytes)` runs on the storage's single writer thread (asynchronously, never on the sensor path): (a) sealed traces with a transferred marker (3.8), then (b) the oldest sealed trace by `endWallMs`; never the running trace nor the running `imu_trace_tmp`. Crossing the soft budget mid-trace schedules a reclaim and **the trace keeps writing**; a failed delete is retried with backoff and counted; reclaim success resumes automatically; **`DISK_FULL` only when physical free space < floor + needBytes after reclaim freed nothing**, then the running trace seals with what it has (`cap` reason `space`) and the recorder retries at each boundary and after each reclaim/deletion. **Recovery never discards sealable evidence because the recomputed soft budget shrank across a restart:** `seal` uses only the physical floor and the sealing reserve, and an over-budget state after recovery triggers reclaim of older sealed traces, never deletion of the recovered one. Lines: `trace reclaim: transferred=<n> oldest=<n> freedMB=<n> failed=<n>`. Tests: `CrossBudgetMidTraceKeepsWritingAndReclaims`, `RecoveryOverBudgetSealsAndReclaimsOthers`, `PhysicalExhaustionStopsOnlyThen` (distinguishes reclaimable pressure), `ResumesAutomaticallyAfterReclaim`, `ReclaimFailureRetried`, `ReclaimOldestNotNewest`, `NeverDeletesRunningTrace`. Per-trace cap unchanged.

### 3.9 Delete all / Forget / range deletion: durable cleanup for autonomous recording (finding 1, Critical)

The old "reuse the fences untouched" is withdrawn. Gaps found in review (verified in the repo by Codex): `CollectSession.control()` carries ranges/tombstones once; `CanvasForgetCoordinator.trySend()` loses them on failed delivery; session-ready resends only the epoch; glasses recovery does not run a pending `trace_forget`; a failed epoch wipe is retried only on another control. Autonomous recording and USB pulling make these gaps reachable without the phone import fence. Design:
- **Phone persists outstanding cleanup** (`outstanding cleanup`: epoch/deletionCounter, ranges, tombstones) in a durable store next to `DeletionEpochStore`; every session-ready resends the full outstanding set; it is cleared only when the glasses status reports `cleanupAckedCounter >= counter` (3.6). A failed send keeps it.
- **Glasses persists received cleanup before acting** (`files/trace_cleanup_pending`, `AtomicFile`), executes it on the storage writer thread, removes it only after every targeted trace, marker and `imu_trace_tmp` is deleted, **replays it at process start** (including before recovery seals anything, so a recovered killed trace in a wiped range is deleted not sealed) and after every reconnection, and retains it after a failed delete until success (retry with backoff).
- **Quarantine until cleanup completes:** while cleanup is pending, affected traces are marked `quarantined` in a sidecar index (outside the trace dir), excluded from `reclaim` accounting for publication, from the hand-over export (the script lists only non-quarantined sealed traces; the glasses publish the list through `run-as cat files/imu/exportable.list`, regenerated after each seal/cleanup), and from any future link transfer. A running diagnostic trace in a wiped range is dropped (`abortLocked`) and the next one starts after the fence.
- Text logs hold counts only. Glasses `capture_diag.log` is kept through Delete all (Q9). The phone `pca.log` IS cleared on Delete all through the writer's acknowledged `clear()` (LGC2 `LogWipeListener`; user-confirmed default 2026-10-23 / Codex lgc2 review #4), with a persisted pending-cleanup request retried at next start; range Forget does not rewrite logs (counts only, no per-line time index). The QnA eval file IS wiped (tier 2, section 5).
