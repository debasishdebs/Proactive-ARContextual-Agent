## 0. The main correction to the redesign doc

The planner/executor covers more than "multi-select only". With `forgetV2` ON, `ForgetService` and `MomentForget` send almost every data-deleting path to `ForgetExecutor`:
`FS:65` (photo), `FS:111` (facts), `FS:123` (retention expire), `FS:130` (suspect removeDescriptions), `FS:149` (photo expiry), `ScopedForget.kt:154` (single at scope Photo), `MomentForget.kt:232-233` (range, Moment ids, Moment/Scene scope -> `FE:260 forgetSpans`), `MarkRecorder.kt:171-172` -> `FE:184 deleteMarks`, and `MW:124` -> `FE:315 wipeMemory`.
When the flag is OFF, only multi-select uses the executor (`FS:106-108`, which fails closed).

The executor does not run the plan, though. `FE` re-plans with `ForgetPlanner` inside the transaction only to revoke leases and check the hash (`FE:59-62`, `FE:121-130`). It then deletes by re-running the v1 steps (`FE:45`: "the delete reads the same database state ... and follows the v1 steps"). So the plan and the delete agree only because the golden tests say so, not by construction.

The executor and planner do not cover these: pins, post-commit cleanup (files, alarms, notifications, export cache, queue scrub, listeners), the dialogs, Delete all's plan, the invalid-Moment purge's Moment removal, vector expiry, and the canvas run delete.

## 3. Notes on hazards

1. **Preview != execute for pins** (G1). The scoped preview counts pins whose Moment `engine.momentsReached` reports. The execution deletes every armed pin whose Moment is gone after the commit, and the arming covers all pins with a live Moment. A Forget that drops a Moment by the radius or a holding rule outside the reached set could delete a pin the dialog did not count. UNVERIFIED in a test; looks reachable from the code.
2. **Stale arming** (G6). `explicit()` arms with `runCatching`. If `cascadeAfter` returns null (corrupt store, save failed), the arming stays. Until it clears, `sweep()` skips (system removals do not de-link). At the next start, `FA:298` deletes armed pins whose Moment disappeared for any reason, including a retention expiry in between. In range (#7) the arming happens before the gate, so a queued retention run can land between arm and commit (the `inRange` reach limits but does not remove this).
3. With v2 ON the semantics differ (F1/F3/F5/F6, nudges ERASE, AskRules v2). `DesignDivergence.kt` lists where the design was not implemented. Flipping the default is a behaviour change, not a refactor.
