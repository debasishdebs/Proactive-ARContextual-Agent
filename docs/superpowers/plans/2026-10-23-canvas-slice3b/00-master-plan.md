## 1. Goal, release target, scope, binding rules

**Goal.** Let the user (a) write a small Python function in the canvas and run it over stored trace items on the laptop in an offline container (Python experiments), and (b) describe a tool in natural language, have a pinned CLI generate it inside an isolated container, verify it offline (generated tests, frozen examples, 200 schema cases, offline debug APK), and see the result as text on the phone after a native confirmation (NL tools).

**Release target: `v1.0.0-alpha`** (release ladder, handoff section 16: after 3b phase 1 = NL tools and Python experiments; before `v1.0.0-beta` = 3c phase 1). Two honest labels:
- "Python experiments" = M0 and M1 COMPLETE (package A, 128.0 agent-h, of which the 7.5 h of S1/S3 spikes are needed only for NL tools).
- "NL tools" = M0 to M3 COMPLETE (whole slice, 187.2 agent-h). An export of `tool-<id>/` or a stand-in never satisfies M3 (Codex 16); M2 is the stand-ins and export and is **independent of the CLI spikes** (round 1, finding 12).

**In scope.** Helper protocol v1 (pairing, poll, lease, payload, heartbeat, result, fail, cleanup); native grants (`py_exec`, `promote`) and native per-job confirmation for `tool_build`; Room v8 persistence with fenced lifecycle, frame-Forget fence and deletion fences; S6 refusal on every publication path; `py.fn` ASYNC-only experiments with runner-level cancellation; `tool.draft` stand-ins and client-side export; one trusted example tool in `:services:orchestration`; rootless Podman helper with profile table, kernel-limited job filesystems and one shared lock launcher; proxy-only generation network; one pinned CLI (Claude Code CLI, API key file, explicit tool list); offline verify with oracle (fresh read-only tree per step); result bundle; gates and stamps.

**Out of scope (deferred with reason; carried from Codex "cut/defer").** RT replay lockstep with Python and Python in sweeps (ReplayService has no node-suspension bridge; P17 pins the refusal); fusion tunables (3a Task 13 absent); LIVE (3a Task 25 absent); second runtime (Docker) and second CLI; AI-assisted stand-ins; promotion machinery and any path that puts a verified tool into the installed app (the 3b output is a text diff plus an APK that stays on the laptop, never installed); CodeMirror or rich editor; patch syntax-highlighting viewer (`patchview.js`); new dependencies, model files and build-script changes in generated tools; mixed-domain projection; repair loop (a failed verify needs a new confirmation); the watch app; any sensing change (S84); **a VM-side liveness watchdog (Q12; the 5 s guarantee is narrowed instead)**.

**Binding rules** (handoff 00, plus part A section 0/5). Sonnet 5.5 implementers only (no Opus, no Haiku); Codex gpt-6.1-sol read-only reviewers, one review per group, none for minors; Codex never implements. 8 GB Mac: Opera closed and `memory_pressure` free >= 25 % before any VM-heavy job; Gradle `--no-daemon -Dorg.gradle.workers.max=2`; **every Gradle and VM start goes through the one lock launcher `tools/canvas-helper/pca_lock.py` (R12): at most 2 host builds machine-wide, 1 while a light VM job runs, 0 while a heavy one runs**; never `git stash`, never machine-wide `pkill`/`killall`, never `gradle --stop`; clean modules before trusting a red gate; no `git push` (the user pushes); no secrets in any output (counts and names only; never read `gen.key`; never print `AssistServer`/device-secret logcat lines); no APKs on GitHub until a release-signed build exists (alpha = tag and release notes only); never uninstall the phone app (SQLCipher key); `adb install -r` only after a phone backup; never install or launch during a call; encrypted-migration device test only on the emulator `MyEmulator`; `PROTOCOL_VERSION` stays 1; DB migrations additive; sensing untouched; LIVE refused. RED test first, then GREEN, then the named mutation check, for every task **and every spike**. Explicit-path commits only. Worktrees under `~/Desktop/rokid/`, moved to `archive/` when done.
