## Built (Part 1)
1. **`MomentType` (FRAME, MARK)** in `services/memory/.../moment/MomentType.kt`; `MomentType.of(frames, marks)` derives it (frames > 0 FRAME, else marks > 0 MARK, else null = not a Moment). Stored as `moment.momentType` (enum name, `NOT NULL DEFAULT 'FRAME'` only for the migration; the Kotlin constructor has NO default). AUDIO is reserved by NOT being a value (no dead branch). Every `when` over it is exhaustive: `MomentBuilder.noPhotoReasonOf`, `SceneCutter.hasFrames`, `CanvasRunner` lineage, `MarkRows.joinedLabel/reasonLabel`.
2. **`NoPhotoReason`** (only `UNKNOWN`) on `moment.noPhotoReason` (null for FRAME). I found NO cheap reliable per-second source (the phone's pause state is live, not stored; the glasses heartbeat is not imported per second), so every MARK Moment says UNKNOWN. Later values are additive (the column holds the name).
3. **Resolver/builder.** `MomentResolver.window/resolve`: a second with a mark and no photo is a MARK Moment (id = the same 8-hex phone second); a second with a photo is FRAME; neither = not a Moment. `Moment.type` has no default. `MomentMark.code` (= `canvas_label.source`: tap, voice, phone_voice, retro, ask_tap) is part of the content hash (a retag rebuilds the Moment) and is stored as `moment_part.code` (a fixed token, never text). `MomentSource.marksNewest` (default over `marks`) feeds the newest-N listing (cap 5000 marks; when the photo read is cut short, older marks are left out so a second is never misclassified).
4. **Rebuild paths.** `rebuildWindow` candidates include seconds that hold a mark (`MomentDao.labelSeconds`), so the 15-minute cadence creates and removes MARK Moments. Mark undo and retag now tell the Moment side (`MarkRecorder.onChanged`, wired in `MarkGraph` to `onMarkRecorded`), so the second is rebuilt in about 500 ms (MARK Moment goes with its mark; the code follows the tag).
5. **One-time catch-up (item 5).** `MomentBuilder.catchUpMarks(now)`: builds the seconds that hold a mark in the last 7 days, then stores `canvas_meta` key `mark_moment_catchup_ms` (a counter) so it never repeats; failure leaves the key unset (next tick retries); store switch off = nothing built, key unset. `MomentBuildTrigger.rebuildRecent` runs it first (`catchUp` constructor argument, production wiring in `MomentTriggers`).
6. **Scenes.** `SceneMoment.type` (no default). `SceneCutter`: a MARK Moment never cuts by frame or activity and is invisible to those rules; the frame/activity comparison is between the last Moment WITH photos of the Scene and the next one with photos (so F1, M, F2 still cuts at F2 and M joins F1); hour and the 5-minute cap still apply to marks. `DaoSceneSource` passes the stored type; sensor activity fallback unchanged (a MARK Moment gets sensor rows only if a trace covers its second; test).
7. **Readers.** `GET /api/moments` rows gain `type` (`photos` is 0 for MARK). `input.moments` item (`CanvasRunner.momentItem`) gains `type` and `marks:[{tsMs, code}]` (additive; `photos` is `[]` for a MARK Moment; the helper's `input` is free-form, only `{id,input}` is checked); `MomentRunTest` key set updated deliberately. Estimates count `photoCount` from photos only (0 for MARK).
8. **Derive inputs.** `DeriveInputs.momentLines`: a mark's NAME is text only for INTENT rows (an intent word); a plain mark is named `MOMENT`, which is not words. So a MARK Moment with no intent word and no memory has no lines and gets no model call (this also removes the meaningless "MOMENT" note from FRAME Moments that had a plain mark).
9. **Forget / lineage.** Moment Forget, range Forget, tombstones, outbox, audit and Delete all needed no change for the row (the `moment` table is wiped as a whole; `MomentForget` already unions MARK parts and labels). One addition: run rows over a MARK Moment carry the `mf:<labelId>` lineage token of each mark, and `MomentForget` calls `deleteCanvasOutputsForFrames(labels)`, so forgetting the mark deletes its run rows. Scene shrink after a MARK Moment is lost: tested.
10. **Activity tab (read-only).** `MarkRepository` (`MemoryGraph.marks`, over `MomentDao.marksIn`, newest first, max 200) -> `ActivityViewModel(.., marks, ..)` -> `ActivityUiState.marks` (`MarkRows`: time, code word, "In a Moment with a photo" / "Moment with no photo" / "Not in a Moment yet", "No photo: reason unknown") -> a "Marks" section in `ActivityScreen` for Today, Week and Month with an empty-state text. No deletion path added (an INTENT row is not listed as a mark).

Mutations (each red, restored): run fences ignore marks; undo, range Forget, photo Forget, Moment Forget (this one SURVIVED until a test used a mark the time range misses and only the projection names) each without the helper call; Scene run without mark lineage. Final run: memory 714, orchestration 1694, phone 1833, 0 failures.
Decision: only MARK Moments list their marks as lineage (a FRAME Moment keeps its photos), so forgetting a mark that sits in a photo Moment does not delete that Moment's run rows (unchanged).

## Decisions I made (please review)
1. AUDIO is not an enum value (reserved by absence); `NoPhotoReason` has only UNKNOWN (no reliable source today: say so, not invented).
2. The mark code goes into the Moment content hash (a retag rebuilds it). Side effect, once: FRAME Moments that hold a mark get a new hash at the next build (REBUILT, their derived fields hidden once until the derive pass rebuilds them).
3. Any label row (MOMENT or INTENT) in a second makes it a mark second (as the old resolver attached them); the Activity list shows MOMENT rows only.
4. `momentItem` gets `type` and `marks` for every Moment (additive); a FRAME Moment's `photos` shape is unchanged.
5. Derive: only INTENT names count as text (see 8 above).
6. Catch-up window 7 days, marker in `canvas_meta`, run by the cadence tick (not at migration time).
7. A MARK Moment is removed at once on undo/retag via the existing trigger (about 500 ms), not inside the label DAO transaction.
8. Marks inside a second whose photo has an unknown capture time are refused with that second (the existing rule drops the whole second); not changed.

## NOT done

- Run rows over a MARK Moment are deleted by Moment Forget and range Forget; a plain mark undo relies on the existing label-rev invalidation only.
