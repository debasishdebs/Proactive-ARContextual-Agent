# Developer dump API (read-only), 26 Nov 2026

Status: BUILT, device check pending (no phone was used). Context.db v18 and places.db v3 are untouched: no schema change, no new stored data, no new setting.

## What it is
A Developer-only, READ-ONLY HTTP API in the phone app plus a laptop client, so the owner can pull all Moments, Scenes, marks, pins and their metadata to his own machine and run offline experiments (Moment to Scene building, image retrieval, captioning, text retrieval, nudges). `context.db` is encrypted at runtime, so the data can only be read through the app, exactly like the other token-paired Developer routes (`POST /api/moments/repair`, `POST /api/moments/locations/import`).

## Gate (owner ruling 26 Nov, replaces the earlier arming and `devDump` switch)
1. The canvas server's existing session: a request without a paired session (token from `tools/m1-run.sh pair <host:port> <code> <fp8>`) never reaches the route (401).
2. Developer mode ON (403 `developer_mode_off` otherwise, checked on every call and again after the read).
3. Host and Origin policy are the router's and are NOT widened: the Host must be `127.0.0.1:<port>` or `localhost:<port>`, or the paired LAN host while "Use from a laptop" is on (421 for anything else). Intended transport is USB: `adb forward tcp:PORT tcp:PORT`, then use `127.0.0.1:PORT`.
4. Rate limit: at most 60 calls a second (429 `rate_limited`, `Retry-After: 1`). Pages hold at most 200 items and 2 MB; a photo is capped at 12 MB.
5. A Delete all that lands while a request reads answers 409 `dump_stopped` and no data. A Forget removes items from the next call on (tombstoned Moments and photos never appear; a pin's link to a forgotten Moment is dropped).
6. Logs: a literal and a count (`dump page n=<count>`), never an id, text or position. The router log line is the route template (`/api/dump/:id/:id/:id`).

## Endpoints (GET, JSON, cursor-paged with `after`, `limit`)
| Path | Answer |
|---|---|
| `/api/dump/manifest` | `dump_id` (names the content: same data gives the same id), counts, first/last Moment, schema and app version, embedding spaces (id, name, dim, state; never the config), which fields exist, `fieldsAbsent` |
| `/api/dump/moments?from=&to=&after=` | per Moment: id, start/end ms, frames (with capture metadata), memories (caption/note text, review state), derived rows (summary, caption, embedding space, build revision, stale), marks, place cards, `placeName`/`placeNames`, `sceneId`, `location` |
| `/api/dump/scenes?from=&to=&after=` | scene rows, member Moment ids, activity, boundary rule, derived text, clusters with summaries and medoid frame ids |
| `/api/dump/marks`, `/api/dump/pins` | marks (with their Moment id); pins (name, coordinates, note, attached Moment) |
| `/api/dump/frames/<id>/photo` | the stored image bytes (JPEG, PNG or WebP), `Cache-Control: no-store` |
| `/api/dump/vectors?space=nomic or siglip2&after=&dtype=float32 or float16` | OPTIONAL embeddings, base64 with dimension. `nomic` = text vectors of memories plus Nomic image vectors, `siglip2` = SigLIP 2 image vectors. Only items that have one |

`from`/`to` are epoch ms or a local day `YYYY-MM-DD`. Moments: `after` = Moment id.

## The one exception to the v18 location rule
The owner asked for the saved location of his own Moments (and the pin coordinates and place names) for his own experiments. `MomentLocationSourceRulesTest` lists `DumpReader.kt` in the allow-list with that reason, and new tests pin that (a) it is the only dump file naming the location store, (b) no other canvas route file does, (c) `DumpDao` is SELECT only, (d) the banned set (AI, connectors, Ask, prompts, exports, `CanvasApi`/`CanvasBackendImpl`) still names no location token, (e) location coordinates appear in `moments` items only, never in the manifest, scenes, marks or vectors. Nothing else changes: no coordinate in an export, a log, a prompt, Ask or the canvas API.
Never included: the SQLCipher key, pairing tokens, the MapTiler key or any API key, settings, the embedding space config JSON.

## Not in the dump (not stored in `context.db`)
Which model wrote a caption or summary and its version (only a build revision is kept): `model` and `modelVersion` are always null and `fieldsAbsent` says so. The audio transcript (no audio flow exists yet).

## How to run
```
tools/m1-run.sh pair 127.0.0.1:PORT <code> <fp8>      # once; phone: Developer mode ON, canvas server on
adb forward tcp:PORT tcp:PORT                          # USB
python3 tools/pull_dump.py 127.0.0.1:PORT              # -> ~/Desktop/rokid/dumps/<dump_id>/ (0700)
python3 tools/pull_dump.py --from 2026-11-20 --to 2026-11-25 --no-photos
python3 tools/pull_dump.py --vectors --space siglip2 --dtype float16   # embeddings only on request
python3 tools/pull_dump.py --selftest                  # no phone needed
```
Folder: `manifest.json`, `README.md` (field meanings), `YYYY-MM-DD/<momentId>/{moment.json,frames/*.jpg}`, `scenes/YYYY-MM-DD.json`, `marks.json`, `pins.json`, `vectors/<space>.bin` + `.index.json` (only with `--vectors`). Resumable: files that exist are skipped. The client uses the pairing state of the other tools (host, `auth.hdr`, pinned `cert.der`), reads the token into memory only, never writes or prints it, prints counts only, and refuses an output path inside a git tree.

## Privacy statement
The dump leaves the phone only over the owner's own USB cable (or the paired LAN session he already set up), to his own laptop, only while Developer mode is on, and only through a paired session. It is read-only: no route here writes, deletes, sends or logs content. The pulled folder holds private data (locations, place names, photos, notes): it is created 0700 outside git; keep it off cloud sync.
