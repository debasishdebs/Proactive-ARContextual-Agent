## 1. Behaviour
- A canvas run still writes NOTHING: `memory.write` stays the preview executor (`MemoryWritePreviewExecutor`, test `theMemoryNodeNeverWritesDuringTheRun`).
- Run control (photo run page, `runNewView`): a pipeline WITHOUT a Save memory node offers one button "Run" (playground: when the run is DONE a dialog "Run output (nothing was saved)" shows the output of the last step(s) only; nothing is stored). A pipeline WITH a Save memory node offers "Run & Save" and "Run, review, then Save". The choice travels as `#/run/<id>?after=save|review|play`; the run page acts once when the run is DONE (a plain link does nothing). A/B starts keep their single "Start". Moment/Scene/watch run pages are unchanged.
- "Run & Save": after DONE the page POSTs `/api/runs/<id>/save` and shows a dialog with the server's message (saved / already saved / the typed refusal text). "Run, review, then Save": a dialog lists the proposed memories (text, kind, "needs review"), "Save" confirms, Close discards (nothing is stored until Save). A DONE run of a pipeline with a Save memory node also gets a "Review & save memories" button on the run page (retry after a BUSY result).
- Server (all in Kotlin): `CanvasRunSave` (orchestration/canvas). `GET /api/runs/<id>/proposal` (read-only) and `POST /api/runs/<id>/save`. The proposal is rebuilt from the stored run rows: what the `memory.write` node received per photo (the runner's own edge rules via `ItemFlow.gather`), deduplicated.
- The save goes through `ExtractSave.saveExtraction` (the live write path: Forget fences, `frame_source` FACT rows, generation fence, one transaction), then the embeddings (`ExtractFollowUp.afterSave`, no nudge, no model call). Never through the preview.
- Provenance: ids `rokid_cv_<runId>_<n>` (facts) and `rokid_cv_<runId>_c<n>` (captions, LONG tier), tag `canvas` on facts, `frame_source` rows to the photos. Review state follows the pipeline's check like the live path: OK only when the extraction was `trusted`, otherwise NEEDS_REVIEW (hidden from export/Moment text until the user reviews it in Memory). Captions are OK. A `summary` fact is saved as a derived memory with `memory_source` edges to the other memories saved from the same photo.
- Valid memories only: a fact/caption whose source photo is not live (forgotten, tombstoned, expired, file gone) is left out; nothing valid = typed `NOTHING` (no marker, a later retry is possible). Not saveable: run not DONE, no memory node (playground), Moment/Scene/watch run.
- Idempotent: `canvas_meta` key `canvas_save:<runId>` (value = count) is written in the SAME transaction as the memories; a retry or double click returns `ALREADY_SAVED` and writes nothing, even after the user forgot one of the saved memories (no resurrection). A concurrent second save rolls back whole (in-transaction check). The marker goes with its run (`CanvasDao.deleteRun`) and with Delete all (`WipeDao`); `DeletionGraph` canvas_meta text updated.
- DataOpGate: new side `DataOpGate.write`: waits, bounded (30 s), until neither an export nor a delete runs or waits, then runs; past the wait it throws `WriteBlocked(byExport)` and the save returns typed `BUSY`. User text: "Not saved: an export is running. Try again in a minute, or when it finishes." / "Not saved: a delete (Forget or Delete all) is running. Try again in a few seconds." An already saved run answers without waiting. Delete all during the save -> typed `WIPED` ("Delete all ran while saving. Nothing was written."). Any other failure is thrown (HTTP 500, the page shows the error banner, nothing stored, retry works); no silent drop.
- Forget: saved memories are ordinary memories: Forget fact, Forget photo (by `frame_source` and `memory.frameId`), retention, Delete all, export validity. `ResidueOracleTest` has three new cases (Forget fact / Forget photo / Delete all of a canvas-saved memory; the run's preview rows hold the text and are removed by the existing frame lineage).

## 4. Decisions for the human
1. **Review state.** A save marks facts OK only when the pipeline's confidence check trusted them; a pipeline with no check saves them as NEEDS_REVIEW (they do not reach export/Moment text until reviewed in Memory). Say if canvas saves should default to OK.
2. **Photo runs only.** Moment, Scene and watch runs are refused (`NOT_PHOTO_RUN`); their items are not real photos. Also no save choice on A/B starts (the run page button is there).
3. **Gate semantics.** A save waits for an export/delete (30 s, shared with Forget) but does not itself block an export or delete from starting (a save is one short transaction guarded by the existing fences).
4. **Moment text lag.** Saved memories reach `moment.text` at the next build (cadence, up to 15 min), like any memory; saves schedule embeddings only (no nudge, no critic call).
5. **Marker residue.** `canvas_save:<runId>` (run id + count, no content) is removed with its run and Delete all, but not when `pruneRuns` drops an old run (it keeps 20); harmless, say if you want pruning to clean it.
6. **Browser pass** to do later: Run & Save and Run-review-save on a pipeline with Save memory (e.g. the built-in capture clone), a playground run on a pipeline without it, the BUSY text while an export runs, the retry button, and that the Save dialog on a run of a forgotten photo says "nothing to save".
