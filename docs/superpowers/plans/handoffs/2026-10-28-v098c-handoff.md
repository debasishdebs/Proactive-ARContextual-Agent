# v0.9.8 slice C handoff (2026-10-28)

Builds on slices A (RagCore) and B (canvas flows). Spec: `docs/superpowers/specs/2026-10-28-v098-query-nudge-design.md` (Slices, C).

## What changed
- **Triggers are real** (`trigger.moment/scene/signal/schedule`, palette on, liveable). Each is the one root of a Nudge flow and feeds the same chain, so quiet hours, daily cap, 24 h dedupe, shown gap, the Forget fence, verbosity and pause apply per trigger. `FlowPlan` gained `trigger`, `maxPerHour`, `signal`, `cron` (defaults keep `BUILT_IN_NUDGE` and the default pipelines equal to the goldens).
- A published Nudge flow runs ONLY on its own root (`NudgeEngine.runOnce(trigger)`; the built-in flow's root is the summarizer pass, unchanged). Any other trigger returns `NotThisTrigger` before anything is read or called.
- **Moment**: `MomentTriggers` build path fires when a build stored a Moment. **Scene / signal**: `MomentCadenceWorker` fires both after the Scene cadence stored Scenes. **Schedule**: `ScheduleTick` runs inside the existing 15 minute `MomentCadenceWorker` (no new worker, no alarm, no wake lock); fires once when a cron occurrence passed since the last check, never replays missed ones, first check only records the time; the last-check stamp is in `canvas_meta` (restart safe). All go through `FlowTriggers` (one cheap plan lookup, 60 s debounce) and a unique `NudgeWorker` run per trigger with `RequiresBatteryNotLow`.
- **Signal**: `trigger.signal` embeds `agg.window` + `gate.compare` (reuses `WindowAggregate.over`/`NumberCompare.holds` and their param schemas) over the sensor summaries of the newest Scenes; fires on the edge (held state persisted). Chosen over chaining the nodes so the Nudge chain stays one linear shape.
- **Cron**: `CronSpec` (5 fields, lists/ranges/steps, no names), floor 15 min (within a day and across midnight), validated in `FlowPlan.shapeProblems` with fixed texts (the expression is never echoed).
- **Rate limit**: `maxPerHour` param (1..12, default 4) on every new trigger; `TriggerRateLimiter` keeps rolling-hour stamps in `canvas_meta`; checked right before the model call, so a gated run does not spend it; a refusal is traced `NUDGE_DROPPED/TRIGGER_RATE`.
- **Pause**: non-summarizer triggers stop under a pause record or Battery Saver (`NudgeRun.Paused`). The summarizer-pass path is unchanged on purpose.
- **IMAGE query**: Moment and Scene triggers pass the newest photo (last 10 min) embedding to `NudgeInputs.build(photoVector)`; `NudgeEngineFactory` now builds a photo-capable `RagCore` (same Ask photo gate, no endpoint = no image is decrypted or attached; photo lines only). A flow can switch it off (`imageQuery=false`).
- **Delivery** (`DeliveryRoute` in core:model, one resolver for both flows): Nudge `phone` = feed row only (`shownOn=phone`), `glasses` = HUD overlay (`toast`), `both` = today's verbosity routing; a Nudge refuses `caller` at publish. Query `phone/glasses/both` via `AskOutcome.route` -> `AnswerResult.route` -> `VoicePipeline` (HUD suppressed or kept, phone `lastAskId`, TTS only on the phone-mic or Bluetooth path); `caller` leaves the pipeline untouched. Glasses not connected (`DeliveryEnvironment`, set by `HubGraph`, unknown = not connected) -> phone, trace row `NUDGE_DELIVERY_FALLBACK` / `ASK_DELIVERY_FALLBACK` with the reason token (and a log line).
- Publish now accepts all of this; refusals: schedule floor/shape and param ranges (cannot even be frozen), Nudge with `caller`, no source chosen.

## Codex review fixes (round 1, 8 findings)
- Query photo: `TriggerImages.photo` returns `TriggerPhoto(frameId, vector)`; the engine checks it is not forgotten, adds `frame:<id>` to the commit fence and the stored `dependsOn`. Embedding space: `NewestPhotoVector` uses the photo only when its space is the ACTIVE image space, else skips with trace `NUDGE_IMAGE_SKIPPED` / `image_space_mismatch`.
- State scope: `FlowPlan.scope` = `p<publishId>` (set by `DaoFlowPlans` for trigger flows); rate stamps, held signal and the schedule state are keyed by it, so a new publish starts clean and never fires retroactively.
- Clock: rate stamps in the future still count; the schedule checkpoint never moves backwards (`max`).
- Schedule: one value `checkpoint;pending` per publication; the occurrence is written pending before the enqueue and cleared only after WorkManager's result confirms the unique KEEP work (`NudgeTrigger.enqueue` now suspends and returns Boolean). A death between the enqueue and the clear can cause at most one extra run (bounded by the rate limit and gates). A search that finds nothing moves the checkpoint to now.
- Cron: DST policy = a local time in the spring-forward gap is skipped that day, a repeated time in the fall-back overlap runs once (first instant); a day's instants are sorted as instants. Only dates that occur every year are accepted (no 29 February, nothing like 31 April; a day-of-month list containing 29 with February selected is refused); the 15 minute adjacency scan covers 2027 and the leap 2028. Tests: Lord Howe, US spring and fall.
- Lookup errors: the engine runs the built-in flow for any trigger when the plan lookup throws; `FlowTriggers` then enqueues a summarizer-pass run (its 30 minute gap applies).
