# v1.1 backlog: Forget lifecycle (decided 2026-10-28, user ruling)

Moment/Scene Forget stays implemented as is in v1, Developer-mode gated (re-checked in the engine at plan, preview and inside the deleting transaction). The in-flight-writer race (Codex e3 finding 1) is ACCEPTED for v1 as a known half-baked item. No further Codex rounds on it before v1.1.

## The user's design (v1.1)
- Every object family (Moment, Summary, Caption, Audio, Object, Person, and the run results) implements `selfDelete()`.
- On Forget: build the dependency DAG of the affected objects; take ONE global lock over all of them. Flows take a read lease from reading their inputs until committing their output; build-time and runtime flows cannot touch locked objects.
- Delete by looping `selfDelete()` over the DAG, null the upstream pointers, release the lock.

## Why (races and divergences the reviews found)
- In-flight peer writes after a scoped Forget: a flow that read its inputs before the Forget commits its output after it.
- Closure growth: batch lineage (`batchId` tokens) grows while the Forget runs; a peer written after the preview is outside the set the user confirmed.
- Preview/delete divergence: the preview's set and the delete's set were derived by different code paths (d.moments vs dropped, named vs auto-removed Scenes, sequential per-photo deletion losing lineage).

## What v1 does instead
Batch peers are regenerable run results, not user data: they are not in the plan hash. The delete computes the lineage closure once, before deleting anything, inside the one transaction, and removes it in one call. The preview shows an estimate. Guard rails (this slice): more than `MomentForget.MAX_UNACKED_RESULTS` (200) rebuilt results needs an explicit acknowledgement carried in the confirm token (`Counts.ackHash` = plan hash + `+ack`; the dialog shows a warning and a tick box); more than `HARD_CEILING_RESULTS` (5,000) aborts with `ForgetTooLarge`.

## Accepted v1 gaps
- CanvasRunner.kt:~682 passes no member photos for photo runs, so a singleton flush after a scoped Forget can restore forgotten-photo text.
- Scoped (Moment/Scene) Forget is dev-only; there is no UI note beyond the existing "experimental until a worn test" Developer-mode copy (`ForgetScopeCopy.EXPERIMENTAL`).
- A flow that is mid-run during a Forget can still write a result that cites forgotten content (the commit fence catches most Ask/Nudge cases, not canvas runs).
- Single Photo/Fact Forget still cascades batch-wide uncounted (as before).

## The review rounds (8) in one list
1. Moment/Scene scope accepted without a Developer-mode re-check: gate moved into the engine (plan, preview, inside the transaction).
2. Outside cited photo's batch peers deleted uncounted: counted, then moved to a lineage closure.
3. Peers found only from outside photos, not from in-span photos or removed Moment/Scene keys.
4. Developer gate check-then-act window (waiting for Room): re-check inside the transaction.
5. Preview of a stale experimental plan not re-gated.
6. Relaunch settle started by a mode callback while telephony was still busy.
7. Preview selected `d.moments`, delete used `dropped` (requested seconds with no stored Moment); auto-removed Scenes' outputs survived.
8. Sequential photo deletion lost lineage (roots A:x, B:x|y, peer C:y left C behind): closure before deletion. The in-flight-writer race (e3) is the accepted remainder.

## Forget single answer / nudge (deferred from small items A, 2026-10-30)
Removed before rc1 after the Codex review. A single-row redaction (`redactAsk` / `redactNudge`) is not a Forget: (1) the question stays in Room, previews, lists and exports (redactAsk clears only the answer and sources); (2) a nudge's text lives on in derived answers/nudges (the RAG `dependsOn` carries source ids, not nudge ids) and an in-flight writer that used it can still commit. Needs a real design: erase question and answer, find and invalidate everything derived from the object, fence in-flight derivatives, then Previewable `forgetTarget()` for Answer/Nudge and the single-object dialog (already built for marks: `ForgetKind.single`, `ForgetCopy.SINGLE_SCOPE`).
