## 1. Design

### One text-in/text-out backend, several interfaces
```
Phone voice   : phone STT --\
Glasses voice : audio -> phone STT --> VoicePipeline --> Utterance.asInterceptor() --\
Home chat     : (no STT) HomeViewModel.ask ------------------------------------------> Utterance.handle(text, source, genuineFinal)
(reserved)    : GLASSES_TEXT ---------------------------------------------------------/        |
                                                                                          MarkCommandParser (the only parse)
                                                                                          UtteranceCommands (effects) -> MarkRecorder
```
- **Where it lives.** `services/voice/.../Utterance.kt` (`Utterance`, `UtteranceSource {GLASSES_VOICE, PHONE_VOICE, PHONE_CHAT, GLASSES_TEXT}`, `UtteranceResult {PassThrough, Handled(replyText), Ask(question)}`, port `UtteranceCommands`). Dependency direction decided it: `:services:voice` depends only on `:core:model` and owns the parser; `:services:orchestration` (the recorder) does not depend on voice; `:phone` depends on both. So the parse and the reply copy are in voice, the DB effects sit behind a port that `:phone` implements (`MarkUtteranceCommands`, a thin mapper command -> `VoiceMark` + origin, no parsing).
- **Adapters, no logic.** `VoicePipeline` still only calls its `UtteranceInterceptor` seam; `Utterance.asInterceptor()` maps `VoiceSource` -> `UtteranceSource` and the results. `MarkVoiceInterceptor` is deleted. `HomeViewModel.ask` calls `utterance?.handle(q, PHONE_CHAT, true)` before `AskService`: Handled -> show `replyText` in the chat (`HomeUiState.reply`), no model call; Ask(rest) -> ask only the rest; PassThrough -> ask as today. A new command is added in `MarkPhrases`/`MarkCommandParser`/`Utterance` only and reaches every surface.
- **Reply copy** (fixed, never the user's words): `✓ marked`, `marked · <intent word>`, `mark undone`, plus ` (no photo: camera busy)` / `glasses not connected` / `glasses not worn` / `glasses can't` for a phone-origin mark with no photo. The same text goes to the glasses HUD toast and the chat.
- **Lexicon.** Added undo phrases `undo the mark`, `undo that mark`, `undo this mark` (`docs/voice-marks.md` updated; the doc test pins it). The bare word `undo` is deliberately not a command (a question everywhere).

### Phone-origin mark photo
1. Phone voice / chat mark: `MarkRecorder.applyVoice(commands, origin, now, phonePhotoReason)`. The mark is a phone-owned label `mk:phone:<utterance start ms>` (reference `phone:<ms>`: a valid `MarkRef`, epoch `phone` never collides with a glasses UUID epoch). Idempotent by that id; a chat mark never reuses an earlier voice listen. It is recorded at once, whatever the link or a call.
2. Decision (instant, pure, `HubMarkPhoto.reasonNow`): link not carrying data -> `glasses_not_connected`; the glasses' last Hello lacks `markPhotoRequest` -> `no_photo_support`; call active (existing `RelaunchGuards.callIdle`) -> `camera_busy`; worn false -> `glasses_not_worn`; wear unknown counts as worn only while capture runs (no active pause) else `glasses_not_worn`. A reason is stored as the label's `photo` (the fallback Moment says it, the reply says it). Null -> the label is `pending` and ONE `pc_mark_photo_request{ref}` is sent (`Channels.MARK_PHOTO_REQUEST`); a send that fails now leaves `glasses_not_connected`.
3. Glasses: `HudController` -> `MarkTap.onPhoneRequest(ref)` runs the SAME photo job as a tap (`MarkPhotoRunner.take(ref)`: explicit camera open, global hold default 3 s, bounded exception when paused, one camera user), bounded: malformed ref ignored, a repeated ref ignored (32 remembered), at most 3 jobs in flight together with tap jobs (a 4th fails fast `camera_busy`), failures reported on `pc_mark_photo` with epoch `phone` + the seq. The glasses Hello carries `markPhotoRequest = true`.
4. Phone: the frame carrying `markRef = phone:<ms>` passes `MarkPhotoAllowance`/`RoomMarkLookup` (label pending, durable one-claim), links in `FrameIntake`, becomes a FRAME Moment; failures/timeouts (`photo_timeout`, 120 s) as for taps. Retro marks never request (`retro_no_photo`).
5. Undo from the chat/voice (`undo mark`, `undo the mark`) goes through `removeMark`: undone marker first, photo forgotten via `ForgetActions` (gated), then label rows deleted. The glasses photo job of an undone phone-origin mark is not cancelled (3 s at most); its frame is refused by the marker.
- Old glasses: they never send `markPhotoRequest`, so the phone records `no_photo_support` immediately (better than the 2 min timeout); a lost message still times out to `photo_timeout`.

### Mark source label (user ruling: no fuss)
A mark made while a phone call was active (existing call detection `HubGraph.callActive()`) carries `;call` on its provenance (glasses taps and phone marks alike); Activity shows `During a call`, every other mark shows no label (no tap/voice/chat/glasses labels). `MomentDao.MarkRow.provenance` is the one added column. Moments rows and the Moments API do not show it (see Remaining).

### Rules
PcLog literal messages only (`mark photo requested`, `mark photo request not sent`); no transcript is stored or logged (the recorder sees `VoiceMark`s); nothing new is stored beyond label rows (provenance tag, `markRef` is `phone:<ms>`), so the deletion inventory/ResidueOracle are unchanged; DataOpGate semantics unchanged (undo and photo-forget use the existing gated path).

## 4. Remaining
- Not run on a device (no devices touched): the first worn test must check: phone chat `mark this moment` with the glasses worn gives a camera light for the hold, `✓ marked` in the chat and a photo Moment; during a call `✓ marked (no photo: camera busy)` and a fallback Moment; glasses off/away `glasses not connected`; `undo the mark` removes mark and photo.
- The `call` tag is on Activity only; Moments rows / API do not show it (a Moment part's `code` is a canvas data token, not display text; showing it needs a part-level field).
- A glasses photo job started for a phone-origin mark that is then undone is not cancelled on the glasses (it ends within the hold; its frame is refused). A `pc_mark_photo_request_cancel` would be additive if wanted.
- The reply for a mixed text (`mark this moment and what is this`) shows only the model's answer in the chat; the mark's confirmation is not shown (the voice path behaves the same).
- Call detection is the relaunch guard (includes a 15 s settle after a call): a mark within 15 s after hang-up is also tagged `call` and gets `camera_busy`.
- Glasses typed text does not exist; `GLASSES_TEXT` is accepted by `Utterance` with no change needed.

## 5. Decisions for the human
1. Reply copy is the existing glasses copy (`✓ marked`, `mark undone`) rather than `marked`; one text everywhere.
2. Bare `undo` is not a command; `undo the mark` / `undo that mark` / `undo this mark` were added.
3. Old glasses get `no_photo_support` at once (Hello flag) instead of waiting for the 2 minute timeout.
4. Wear unknown + connected + capture running is treated as worn; a paused capture with unknown wear says `glasses_not_worn`.
5. Phone-origin marks are labelled `phone_chat` / `phone_voice` internally only; the UI never shows the source.

## 6. Codex review round 1 (NOT READY, 3 Important) and the fixes
1. **Phone photo request bounded by time (glasses `MarkTap.onPhoneRequest`).** The request now carries `atMs` (phone clock at send) and `sessionStartMs` (additive). Refused: no clock or older than its own session; a ref older than 60 s or more than 5 s ahead of the phone clock; a request sent more than 60 s ago / 5 s ahead. The glasses have no hello offset, so the phone clock is estimated with the offset (glasses wall - phone `atMs`) learned from the FIRST request of a session (reset on session close). Consumed refs are kept 130 s (longer than the freshness window) and evicted ONLY when expired, never by count. Every request that reaches the glasses counts in a rolling minute; the 7th gets `rate_limited` (new token; shown as "too many photo requests in a minute"); the 3-in-flight bound stays (`camera_busy`). Mutations killed: no age check, no sent-age check, no rate limit, eviction by count, refused requests not counted, offset never reset, no consumed check (`MarkTapPhoneRequestTest`). Two tests passed for the wrong reason at first and were fixed.
2. **Session check (glasses `HudController.acceptMarkPhotoRequest`).** The request reaches the runner only when the session is open, the app not exited, and `sessionStartMs` equals the phone session start seen on the phone's other messages (wear/plan/phone-ctx; cleared on close). Otherwise ignored and best-effort answered `session_closed` (nothing is sent after an exit). `MarkTap.onSessionClosed` resets the learned clock. Mutations killed: no open check, no same-session check, session start not recorded, answer after exit (`GlassesRuntimeTest`). The `exited` check alone is redundant (an exit closes the session) and its mutation survives by design.
3. **Truthful undo.** `UtteranceCommands.apply` is now `suspend` and returns `CommandOutcome(noPhotoReason, failure)`; `Utterance.handle` and `UtteranceInterceptor.intercept` suspend; `VoicePipeline.think` runs the interceptor inside its work job (UNDISPATCHED, then `yield` before the answer, so a non-suspending interceptor behaves as before; the generation check drops a stale result). `MarkUtteranceCommands` awaits `applyVoice`: success `mark undone`; `DataOpGate.ExportInProgress` -> "Couldn't undo: an export is running. Try again in a minute."; `WriteInProgress` -> "...a save is running..."; any other failure -> "Couldn't undo the mark. Try again." (a failed mark: "Couldn't mark this moment. Try again."); a failure is never followed by an ask. The mark and its photo stay (the recorder's marker makes the retry idempotent). Tests: `UtteranceSurfacesTest` (a refused removal on chat, phone and glasses voice, then success when free; another failure), `UtteranceTest`. Mutations killed: failure swallowed (export, other), failure ignored in `Utterance`, wrong text. Not covered: the real 30 s gate wait (`DataOpGate.shared` is not settable from `:phone`; the typed exception is covered by `MarkUndoGateTest`); catch order Write vs Export in the adapter has no phone test.
