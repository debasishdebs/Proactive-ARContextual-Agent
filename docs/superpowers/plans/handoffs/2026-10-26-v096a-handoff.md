## 1. Moments carry text
- Schema v14 (`MIGRATION_13_14`, `14.json`): three nullable columns on `moment`: `text` (timestamp + visible memory text), `transcript` (its OWN object; scaffold, the builder always writes null), `errorReason` (explicit reason of the photo-failed fallback mark-only Moment; slice C will write it). The intent (`<id>:i` label) and the summary (`object_derived`) stay separate objects and are never merged into `text`.
- Text format: ISO-8601 UTC timestamp of the second, then one line per visible memory of the Moment's photos (photo order, memory time, id). Null when there is no visible memory text (MARK Moments and photo Moments without a visible fact: the text is the optional part).
- Visible = the export's validity (`ExportDao.memoryPage`): reviewState OK, a derived memory needs a source that is not forgotten, the photo must be live (read through the live frames). `CanvasDao.momentVisibleTexts`.
- Build/rebuild: `MomentResolver` computes `Moment.text` (not part of `contentHash`: the memory revisions already are), `MomentBuilder` stores it on every build/rebuild (cadence, trigger, `POST /api/moments/rebuild`). A rebuild keeps `errorReason` of a MARK Moment (it cannot derive it) and clears it when a photo makes the Moment a FRAME Moment.
- Forget/undo: unchanged paths. Forget fact/photo/undo drop the whole holding Moment (`MomentDao.dropHolding`), so the text goes with it; the next build never writes a forgotten, hidden or stale-derived memory back. Covered by `ResidueOracleTest.momentTextOfAForgottenFact...` (scans `moment.text`), `DeletionGraphWipeTest` (Delete all), the DeletionGraph description and the design doc table.
- Exposure: `GET /api/moments` rows carry `"text"` (JSON null when none); the `input.moments` run item carries `"text"` too (that item is also what a laptop-helper job receives; see decision 2).
- Known lag: a memory flipped to NEEDS_REVIEW (not forgotten) leaves its line in the stored text until the next build of that second (cadence, up to 15 min). The resolver (GET, runs) is always current.

## 2. One-time purge (`InvalidMomentPurge`, `MomentValidity`)
- Invalid stored Moment = id is no second, OR FRAME Moment with no live photo with a capture time (frame row present, not tombstoned, `frame_meta.capturedAtMs`), OR MARK Moment without a non-empty `errorReason`. The fallback-valid predicate is `MomentValidity.isFallbackMark` (MARK with non-empty error reason). The 2026-10-25 01:50 plain mark Moments are deleted.
- Deletes through existing paths in the `DataOpGate` delete side: `MomentDao.remove` (parts, sensor rows, audit, derived, trace deps, Scene shrink with FORGOTTEN audit), a `moment_tombstone` per second (the builder and frame intake refuse it, so a rebuild or `rebuildDay` never brings the Moment back), run rows keyed `moment:<id>`; memories with a photo provenance whose every source frame row is gone (`MomentDao.orphanMemoryIds`, the complement of the export orphan clause) through `ForgetService.forgetFacts` (vectors, edges, asks, derived descendants, outbox rows), then `ForgetActions.apply` (files, cached export, re-summarise).
- Trigger: `ForgetStartup.run` (MainActivity, every launch) BEFORE the cadence is scheduled. Marker `canvas_meta` key `invalid_moment_purge_v1_ms` is stored LAST (even when nothing was found); a failure or a running export (DEFERRED) leaves it unset and the next start finishes (idempotent).
- Logs (PcMoments, literals with counts only): `invalid purge start`, `invalid purge done: scanned=N deleted=N memories=N`, `invalid purge deferred: export in progress`, `invalid purge failed (<class>)`.
- Safeguard still yours: phone backup (manual adb tar) before installing; counts are in the log.

## 5. Decisions for the human
1. **Orphan memories vs retention.** The ruling deletes memories whose source frames no longer exist. Retention (`expirePhotos`) deletes photos at `photoDays` and KEEPS their memories by design, so on a device every memory whose photo expired is deleted by the purge (the export already hides them). If that is not intended, narrow `orphanMemoryIds` (e.g. require no `frame_meta` row) before shipping; the purge counts show the number.
2. **Text reaches the laptop helper.** `input.moments` items (and so a helper `py_exec` job and Prompt nodes) now include the memory text; the previous contract said "never a word". Say if it should be browser/canvas-only.
3. **Marks are kept.** The purge deletes the Moment and tombstones its second, not the bare mark (the mark stays in Activity as "no Moment"). Until slice C (mark touches capture + fallback) every NEW mark still builds a plain MARK Moment that this one-time purge never revisits; consider not storing a MARK Moment without an error reason once slice C lands.
4. The tombstone also means a later fallback Moment can never be built for an old purged mark's second (irrelevant for new marks).
5. No encrypted (SQLCipher) migration run and no device run were done; `DaoFence` was not needed (no insert path), the delete epoch is not consulted.
