## Built
1. **Summary (`proc.summary`, Process).** Input ports JSON (what a Prompt returns), EXTRACTION, MOMENTS, SCENES (never PHOTOS: no image goes with it). Output port SUMMARY. One model call per item through `ctx.model.complete(Role.SUMMARIZE, ctx.callClass)` (the router, the user's SUMMARIZE binding, structured output; no new client), the item inside a `BEGIN_DATA upstream` block with the fixed text `SummaryNode.TEMPLATE` (a Scene item carries only its fresh visible text, as before: a hidden or stale derived field never reaches a node). The model answers `{summary, confidence}` (schema in `SummaryNode`, strict). Result = an Extraction with ONE fact of type `summary` carrying that confidence, so the Confidence check (mean/min/max against the cutoff) and Save memory (preview: row kind fact, SHORT, OK or NEEDS_REVIEW) read it with no executor change. Costs: nominal = max = items; estimate names the SUMMARIZE binding (`CanvasBackendImpl.roleOf`); usage and lineage as Prompt (batchId `run:node:item`, plus the runner's `mf:<frame>` member tokens for Moment and Scene items, so a Forget deletes the rows). Errors are fixed texts: NOT_SET (unbound, no call), BAD_INPUT (Photo or Preview item, no call), NOT_JSON, INVALID_OUTPUT (the call is counted), or the exception class name with the cause kept for the runner. Palette: Process group (generated); no params, so the inspector has nothing to show.
2. **Aggregate (`agg.window`, family Aggregate, domain ASYNC).** Input SCENES or MOMENTS, output NUMBER, no model, no clock. Params (strict schema, served with defaults): `feature` in seconds, gyroMean, gyroMax, accVarMean, accVarMax, stepHzMean, stepHzMax (default gyroMean); `op` mean|min|max|count (default mean); `window` int 1..50 (default 10). For each item (run order = time order) the value is `op` over the feature of the last `window` items up to and including it; the feature is read from the item's `sensor` summary (the Scene's `SensorSummary.toJson`); an item with no sensor summary adds nothing to a window (count 0.0 for an empty window; an empty mean/min/max is the fixed error NO_DATA, nothing flows on). Output item = `{"value": n, "n": values used, "feature", "op", "window"}`. The runner hands the executor the whole run as ONE chunk (`chunkSize = Int.MAX_VALUE`), the only way a node can look back over items. The "Coming soon" line under Aggregate disappears (palette: any registered type of the family).
   **`gate.compare` (Condition, "Compare number")**: the smallest adapter, because the existing Threshold is a glasses gate over MOTION_EVENT and Switch compares strings. Input NUMBER, output NUMBER (passes through), branches `yes`/`no`, params `operator` >=|>|<=|< (default >=) and `cutoff` -1e6..1e6 (default 0.5). BAD_INPUT when the item has no numeric `value`.
3. **Starter (`starter-moment-summary`).** New built-in, read-only, clonable, seeded by `ensureBuiltIns`, listed after the others. Nodes = the Default capture nodes and wires UNCHANGED + `moments -> ask (Prompt) -> sum (Summary) -> trust (Confidence check) -> write (Save memory)`; `trust` goes to `write` on both `trusted` and `unsure` (the review flag shows in the preview). It passes `PipelineValidator`, compiles to the identity plan (hash f5782e0d8610), is NOT an interpreter and never publishes (Moments are tier 3, `PlanShape.tier3Nodes == [moments]`), and RUNS on two Moments in `StarterMomentRunTest` (4 calls: Prompt and Summary per Moment). The Prompt node has a fixed template (describe the Moment from the data) and schema `{description}`. No glasses->Moments edge is stored (the validator only allows capture -> Photo); the merged view's dashed link draws it.

## Decisions taken (please review)
1. **Summary's SUMMARY port carries an Extraction at run time** (one fact, type `summary`, the model's confidence). Smallest change: the two consumers did not change. Cost: it shows as a "fact" in the preview (row kind `fact`, type `summary`, tier SHORT), and the Confidence check's mean is over that one fact, i.e. the model's own self-reported confidence. If Summary should become a real value kind (`CanvasValue.Summary`), the two executors and `CanvasValueJson` change.
2. **`starter-moment-summary` is a new built-in** instead of an extension of `starter-capture-extract` (a pipeline has exactly one input root: Photo and Moments cannot coexist). The old starter and its hash are untouched. The glasses lane is included (like the old starter) although the pipeline cannot publish; remove it if you want the phone chain alone.
3. **`agg.window` is a trailing window over the run's items**, one number per item, not one number for the whole run. With `window = 50` and `op = max` the last item holds the run's maximum. `gate.compare` is the new adapter node (not an extension of Threshold or Switch).
4. **No sensor summary yet on Moment items** (`momentItem.sensor` is null in `CanvasRunner`), so `agg.window` over a Moments input yields NO_DATA (count 0) until Moments carry the summary; Scenes already do. NO_DATA is an item error (counts in the run's failures), not a zero.
5. A Scene item with no text still gets a Summary call (cost and a low-confidence answer); not gated. A cheap "no text, no call" rule is a follow-up if it matters.
6. `liveable` stays true on the new types (the palette hides `liveable=false` types, and the Aggregate group would stay empty); the interpreter shape rules, not that flag, keep them off the glasses (tests above).
7. New Gradle test count is large partly because each run test builds a Room DB; nothing in production code reads these tests.
