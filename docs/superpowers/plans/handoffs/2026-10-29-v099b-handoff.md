## What landed (phone)
- Dependencies: `play-services-wearable:19.0.0` and `kotlinx-coroutines-play-services:1.9.0` (both in the offline cache).
- `PcaWatchListener` (WearableListenerService, manifest filter `MESSAGE_RECEIVED`, path prefix `/pca/motion`) calls the pure `PcaWatchLink.handle(path, data, sourceOn)`, which feeds the same `WatchMotionIntake.current` (hub sink, `watch=` / `watchRej=` counters, `WatchSource`). New `WatchMotionIntake.acceptLink(json)`: no caller/cert gate; requires `source == "pca_watch"` (`bad_source`); keeps `not_enabled, too_big, malformed, version, stale_seq, rate`, the 1 s coalescing and `(epoch, seq)` persistence.
- Active watch source: `ContextSourceSettings.activeWatchSource` = `watch_app` | `none` (default none), stored as the `src_watch_app` switch in `ctx_hub_state` (already excluded from backup). One-time migration at construction: the old `src_watch_livefit` flag and `livefit_cert_sha256` are deleted, source starts as none. Source id renamed `watch_app` in `WatchSource`, `ContextHub`, `ContextSourcesSettings`, `PermissionPlan` (`SettingsDeps` and `CaptureTimingStore` hold no reference to it). `WatchSource.start()` no longer needs a pinned certificate.
- Drops are never silent: source not `watch_app` -> `source_off`, hub not running -> `hub_off`, wrong path -> `bad_path`; counted in `WatchLinkState` (reason map) and in the hub `watchRej` counter; nothing stored. `WatchMotionProvider` is kept (exported, manifest unchanged) and goes through the same gate (no intake -> `not_enabled` + counted `source_off`). Its LiveFit caller/cert checks are untouched (the pin is gone, so a LiveFit forward answers `bad_cert`).
- Status row (Context sources, shown only when the source is on; the Data Layer is probed only then, on the screen's 5 s tick): `Watch app not installed or not paired` (connected nodes with capability `pca_watch` = 0), `Watch app not reachable` (query failed, nothing recent), `Last motion: <STATE>, <HH:mm>` (accepted within 15 min), `Watch: no data in the last 15 min`. 15 min is a UI constant (`WatchStatusModel.QUIET_MS`), no setting. The old LiveFit notices (missing, multi-signer, re-toggle hint) are no longer rendered.
- Setup: new optional `Step.WATCH` after GLASSES (8 steps). Shows `Waiting for the watch...`, turns to `Watch link confirmed` on the first accepted message (sticky), offers "Turn on watch source" (needed because the default is off), "Skip" or "Continue"; never blocks. Same model behind the "Check the watch link" button in the Context sources watch card (inline line, not a separate screen).

## Hub freshness rule for an old watch value (documented, not changed)
`ContextFusion`: `watchFresh = age(w.atMs) <= p.watchTtlMs`. `ContextHub` passes `FusionParams(watchTtlMs = 1_500_000)` = 25 min (the `FusionParams` default is 1_800_000 = 30 min; the design note says 30 min, the hub actually uses 25). The user fusion overrides may change it. A stale value simply stops counting (walk, vehicle and asleep need `watchFresh`); the UI 15 min line is independent of it.
