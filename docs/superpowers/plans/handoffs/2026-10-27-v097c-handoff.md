## Design

User ruling: ONE setting "Forget scope" = Photo (default) | Moment | Scene for every granular Forget (Forget photo, Forget fact, Forget Moment, any other granular entry). Delete all and Forget a time range are unaffected.

### Scope semantics (engine = `ScopedForget`, `:services:memory`)
- Levels: FACT/PHOTO = 0, MOMENT = 1, SCENE = 2. Effective scope = max(setting, level of the entry): a Forget invoked on a Moment never forgets less than the Moment, on a Scene never less than the Scene (a Moment/Scene entry with setting Photo is the Moment/Scene).
- PHOTO: `ForgetService.forgetMoment` (frame, file, vectors, memories, run outputs, radius path) + one `moment_tombstone` for the photo's own second (`fenceOwnSecond`, only from this entry; never retention, never mark undo). Neighbouring photos survive and may form their own Moments. (The own second tombstone also refuses a second photo captured in that very second: accepted, stated in the handoff.)
- MOMENT: spans = the Moment's second extended by the radius (`ForgetRadius.ms()`, default 10 s) -> `MomentForget.forgetSpans` (the same code as range Forget: photos, memories, marks, traces, sensor rows, run outputs, projection, outbox, `momentForgetRanges` + a tombstone per second) + post-commit `ForgetActions` cascade (export cache, reminders, notifications, outbox, queue scrub) + `ForgetListeners.rangeForgotten` per span (trace files, glasses).
- SCENE: spans = union of the windows of ALL the Scene's Moments plus the Scene's own `[startMs, endMs]`; same as MOMENT and, in the same transaction, the Scene itself is removed (`SceneDao.remove`: rows, parts, audit, derived) and the `moment:<id>` / `scene:<id>` run rows are deleted explicitly (not only through lineage tokens).
- FACT with MOMENT/SCENE: the Moment(s) of the fact's cited photos (`memory.frameId` + `frame_source`), capture time = `frame_meta.capturedAtMs` else `frame.ts`. A fact with no photo falls back to PHOTO behaviour (the fact only). A photo/fact whose Moment is not in a built Scene with scope SCENE falls back to MOMENT. Decision D3.
- Everything runs inside `DataOpGate.shared.delete` (typed outcomes DONE / SAVE_IN_PROGRESS / EXPORT_IN_PROGRESS / CACHE_CLEANUP_FAILED / FAILED, dialog names the reason and when to retry).

### Counts API
`ScopedForget.preview(target, scope): ForgetPreview(effectiveScope, photos, memories, marks, moments, scenes)`: read-only, uses the SAME discovery function as the delete (`MomentForget.discover`), so the numbers equal what a Forget removes (tested: preview == the delete's own counts). `MemoryForget.preview(kind)` -> VM loads it when the dialog opens; the dialog shows the scope in plain words and the counts; for SCENE the Forget button stays disabled until the counts are shown.

### Setting
`ForgetScope` + `ForgetScopeSetting.provider` (like `ForgetRadius`) in `:services:memory`; stored in `CaptureTimingStore` (prefs `capture_timing`, key `forget_scope`, validated: anything not PHOTO/MOMENT/SCENE -> PHOTO) next to the photo Forget radius and Scene rebuilds per day in Settings > Capture; three choices with one line each. Log: event names only (`forget scope changed`). Backup: same as the photo Forget radius (prefs `capture_timing` is excluded from backup and transfer: a restore returns to Photo = the safe default). Decision D4.

### Behaviour with the default (Photo) vs today
Photo scope = today's Forget photo / Forget fact exactly, EXCEPT: Forget photo now also fences the forgotten photo's own second (a `moment_tombstone` and a one-second `momentForgetRanges` entry). Consequences, stated on purpose: (a) the second can never rebuild a Moment; (b) ANOTHER photo captured in that very second survives as a photo but cannot form a Moment and a late photo or mark in that second is refused; (c) Forget fact at Photo scope has NO fence (it is the unchanged `forgetFact`). Retention, Invalid-Moment purge and mark undo call `forgetMoment` without the flag: unchanged.

## Remaining
- No UI to start Forget Moment / Forget Scope from a Moment or Scene screen (the engine entry `ForgetActions.forgetScopedOutcome(ctx, ForgetTarget.Moment/Scene)` and `previewScoped` exist and are tested; the canvas has no Forget entry and its JS budget is 4668). An HTTP route + JS button is the next slice if wanted.
- Photo scope counts for a single photo/fact are an exact preview of the rows and marks the cascade removes in the simple cases tested; a photo whose memories are cited by other photos is counted conservatively.
- Not verified on a device: the dialog on the phone, Settings page layout, glasses follow-up of a Scene Forget (traces are fenced by the same listener as a range Forget).
- A Forget while a Moment/Scene run is in flight relies on the existing fences (`frame_forget_rev`, `momentForgetRanges`): not re-tested for the new entries beyond the oracle.

## Decisions
- D1 Mark undo keeps its photo-only Forget (an Undo, not a Forget); say if scope should apply.
- D2 No UI for Forget Moment / Forget Scene (the canvas has no Forget entry; JS budget). The engine entry exists and is tested.
- D3 Fact with no photo falls back to Photo; Scene scope on a Moment not yet in a Scene falls back to Moment.
- D4 `forget_scope` lives in `capture_timing` (excluded from backup like the Forget radius). Reason: a restore must never silently arm the most destructive level; one line in `backup_rules.xml` + `BackupRulesTest` if you want it restored.
