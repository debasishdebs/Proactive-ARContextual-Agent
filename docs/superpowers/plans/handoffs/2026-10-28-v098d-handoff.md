# v0.9.8 slice D handoff (2026-10-28)

Spec: `docs/superpowers/specs/2026-10-28-v098d-device-capabilities.md`. Builds on slices A-C.

## What changed
- `DeviceCapabilities` / `DeviceCapability` (core:model): four fixed entries (`phone|glasses` x `mic|display`), default all on, `constraint` `hud` on the glasses display, `deliveryWarning(target)`.
- `DeviceCapabilityStore` (phone, prefs `device_capabilities`, only switched-off keys, bad keys dropped at load). Backup: EXCLUDED (backup_rules, both sections of data_extraction_rules, `BackupRulesTest`), following `signal_config`/`fusion_settings` (per-device setting; a restored phone may pair with other glasses). Delete all leaves it (no memory content).
- Editors: phone Settings > Devices > "Mic and display" (`SETTINGS_DEVICE_CAPABILITIES`, in `LIVE_SETTINGS`); canvas JSON route `GET /api/devices`, `POST /api/devices/capability` (`DeviceRoutes`, registered in `CanvasExtras`).
- `DeliveryRoute.resolve(..., caps)`: a switched-off display is not a surface; fallbacks `phone_display_off`, `glasses_display_off`, `no_display_enabled` (always a stored phone row), recorded in the existing `ASK_DELIVERY_FALLBACK` / `NUDGE_DELIVERY_FALLBACK` traces. `caller` changes only for a glasses-voice ask with the glasses display off (answers on the phone, no HUD, no TTS). `NudgeEngine.routeOf` applies the same rules (SILENT verbosity is never raised). `DeliveryEnvironment.capabilities`, set in `ContextApp` (workers see it without the hub).
- Mic: `VoicePipeline.glassesListenStart/phoneStart` refuse a listen with a fixed text (`VoiceCopy.*_MIC_OFF`, outcome BLOCKED); `Utterance.handle` answers `Handled(...)` for a voice utterance whose mic was switched off mid-listen. Typed text (`PHONE_CHAT`, reserved `GLASSES_TEXT`) is unaffected.
- Publish: `CanvasPublisher.Outcome.Published.warnings` (default empty); `publishFlow` warns when the only delivery target is off; the publish JSON carries `warnings` only when non-empty; the canvas notice appends it (versions.js, same line, no line added).
