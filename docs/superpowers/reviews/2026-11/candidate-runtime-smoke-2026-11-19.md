# Candidate runtime smoke on the emulator, 2026-11-19

Build: ~/Desktop/rokid/backups/apks-v110-cand-55fa38eb/ (git 55fa38eb). Target: emulator-5554 only (AVD MyEmulator, headless). No other device touched. Emulator stopped with `adb emu kill`.

## What was done and results
1. Phone APK: the emulator's old copy had a different signature (INSTALL_FAILED_UPDATE_INCOMPATIBLE), so com.rokid.context and com.rokid.context.glasses were uninstalled on the emulator only, then both installed fresh. Manifest runtime permissions granted with `pm grant`. Launched, waited 90 s: zero FATAL EXCEPTION / ClassNotFound / NoSuchMethod / SerializationException in logcat (also zero after all later UI steps). Process still alive at the end.
2. Glasses APK: installed, CAMERA granted, launched, process alive after 20 s, no fatal error. Not exercised: camera, Rokid hardware/SDK, display, sensors, phone-glasses link.
3. Shadow-eval route: Developer mode toggled in Settings > Diagnostics > Developer. The canvas starts on loopback 127.0.0.1:8765 when Developer mode is on (HTTP, needs a token). Turned on "Use from a laptop" (HTTPS 10.0.2.16:8765), paired with the on-screen code via POST /api/pair through `adb -s emulator-5554 forward` (Host header set; certificate pin not checked, emulator only). GET /api/proactive/shadow-eval with Developer mode ON: HTTP 200, `text/plain; charset=utf-8`, `verdict=NOT ENOUGH DATA`, observed_days=0, would_show=0, only counts and fixed labels, no free text.
   - 403 developer_mode_off with Developer mode off: NOT verified live. Turning Developer mode off stops the canvas server (connection fails, curl rc=35), so the route cannot be reached with it off. That path is covered only by the unit test (ShadowEvalRouteTest), not at runtime.
4. Place Guide: the Settings > Place Guide row is itself Developer-only (SettingsRoot), so with Developer mode OFF the row (and so the screen and 'Card position') is not reachable: row absent confirmed before enabling and again after disabling. With Developer mode ON the row appears and the screen opens with "Card position (Developer)" and a Position selector (default Centre) plus its explanatory text. Screenshot: candidate-smoke/place-guide-dev-on.png. The screen's own gating on the developerMode parameter was not tested with the screen open and the switch off.
5. Settings > Privacy > Pause zones: Privacy opens, "Open pause zones" opens the map screen without a crash ("Map with 0 pause zones", Draw a box, Fit, no-fix message). The "Offline map" section renders ("No offline map is selected: the plain grid is used..."). No PMTiles file was loaded, so tile rendering was not exercised.

## NOT verified
Real glasses (card rendering, placement geometry, delivery), GPS/location fixes, camera, Wi-Fi/captive portals, Overpass/Wikipedia fetches, Bluetooth, the watch app, real Developer-mode-off 403, offline map with a real PMTiles file, anything over the 90 s idle window on a long soak. The emulator showed an unrelated "Digital Wellbeing isn't responding" system dialog on first boot (dismissed with Wait).
