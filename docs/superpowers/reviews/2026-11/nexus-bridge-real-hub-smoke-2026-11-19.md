# PCA Nexus bridge against the real Nexus hub, emulator only (S1.5), 2026-11-19

Emulator `emulator-5554` only (AVD MyEmulator, API 34, no glasses, no Hi Rokid). Counts and states only; no content. No real device was addressed. Screenshots: `nexus-real-hub-smoke/` (01 pending, 03 approved plus skills section, 05 host on Nexus, 06 bridge uninstalled).

## What ran

- Hub: debug build of upstream Nexus v2.6.0 (tag `sdk-v0.27.0`, commit `7b16cec2e500205c1d04d2a9e069f72430aeb1d2`, versionCode 20600), built on 2026-11-17 with `:phone-hub:assembleDebug` (needs the `CxrGlobal` sibling). The already-built APK was used (no rebuild needed). Backed up with the build commands and SHA256SUMS to `~/Desktop/rokid/backups/nexus-hub-v2.6.0-debug/` (APK sha256 `c8c080ca...34d9b5`).
- PCA phone `phone-debug.apk` and `nexus-bridge-debug.apk` from `backups/apks-v110-cand-5bd9fc6f` (PCA 5bd9fc6f). The older copies on the emulator had a different signing key, so both were uninstalled on the emulator first and reinstalled; hub `BLUETOOTH_CONNECT` and PCA runtime permissions were granted with `pm grant`.

## Results per item

1. **Discovery and approval: PASS.** The hub discovered the bridge on its own (no hub restart) and listed "Proactive Context Agent" as "UNVERIFIED INSTALLED PLUGIN", state **Pending**. Capability rows: Replace the glasses assistant, Offer skills, Speech to text, Show on your glasses, Text to speech (five toggles, all pre-selected; the manifest's `surfaces,stt,tts,assistant` shows as these; "Offer skills" is the row for the skills catalog). Following checklist step 3, Speech to text, Text to speech and Replace-assistant were unticked before "Allow on glasses"; the state became **Approved**, the hub logged `plugin registered package=io.github.pca.nexusbridge plugin=pca status=approved`, and the per-plugin rows (activity, pin, float, floating mode) appeared. The three unticked rows stayed off after approval. Note for the checklist: "Offer skills" is a fourth pre-selected capability (left on here; it has no effect without an approved Assistant caller).
2. **THE KEY CHECK, skills catalog: ACCEPTED.** The hub did not show "skills are turned off: Nexus cannot read their declaration". After approval it shows a valid SKILLS section: "An assistant you allow here can ask Proactive Context Agent for these operations ... No assistant may use skills yet. Allow 'Use skills from other plugins' on it first." So the real catalog (4 operations: status, pause_capture, resume_capture, mark_moment; `data:["status"]`, enum outputs) parses in the hub's own parser. **Limit:** this hub version lists the individual operations only once an approved Assistant caller exists, so the four operations were not shown on screen; the verdict rests on the absence of the "turned off" text and the presence of the valid section (same signal the S1 probe used).
3. **PCA Settings > Rokid Nexus with the hub present.** Developer mode is required to see the row (Settings > Diagnostics > Developer mode). With host PCA: state title "Off" (both apps installed, bridge trusted). The host option "Rokid Nexus" was enabled; switching to it gave **"Waiting for Nexus"** (bound to the bridge, nothing sent yet), and `nexus bind bound`, bridge process started, bridge registered approved. Switching back to PCA: trip `MODE_OFF`, `nexus forget history code=OK`, hub log `notice history purge queued owner=pca reason=owner_forget`, `nexus wipe acknowledged`, `nexus unbound`. So the history wipe path to the real hub works (first real PCA-to-hub call; result OK). The "capability denied" text for the unticked rows was NOT seen (needs a HUD call answered NOT_GRANTED, see item 4).
4. **Publish with the host on Nexus and no glasses link: NOT TRIGGERED.** The PCA phone's own gates stop every HUD publish before it reaches the bridge: the log shows `nexus dropped reason=NOT_WORN` about every 15 s (the capture-state pin), because "worn" comes only from a glasses link (`Hub.lastWorn`, or the wear estimate from a live glasses session). There is no Developer or test route to inject a worn state, and the bridge cannot be called from outside PCA (signature permission). So the hub's CAPABILITY_NOT_AVAILABLE answer to the real bridge, the quiet give-up, the status string and the retry count were not observed. What is known: PCA dropped quietly (one line per tick, no retry, no crash), and the S1 probe (same hub) earlier showed CAPABILITY_NOT_AVAILABLE for a plugin push with no link. Only the real glasses link (S2) or a worn-state test hook can close this.
5. **Hub force-stop: PASS for recovery, cold-start window NOT measured.** After `am force-stop` of the hub, the bridge itself restarted the hub within about a second (`Background started FGS callingPackage=io.github.pca.nexusbridge`, `BusHubService created`) and the plugin re-registered as **approved** with no new prompt (about 1 s). The "first push NOT_REGISTERED, then recovery within about 2 s" window needs a push, which item 4 could not make.
6. **Bridge uninstall: PCA fell back; one BUG found and fixed.** Uninstalling the bound bridge: the bridge was released (`nexus bridge gone`), the hub showed "No plugins installed", no PCA notification remained on the phone, the history wipe had already been acknowledged. PCA's HUD host stays whatever the user chose; with no bridge nothing is sent (PCA's own glasses app draws when host is PCA; with host Nexus and no bridge PCA sends nothing to Nexus). **Bug:** Settings said "Bridge not trusted: an app named like the bridge is installed but is not signed with the same key", and stayed there after "Check again", although the bridge package was gone. Cause: `NexusProvider.onPackageChanged` treated "not trusted" and "not present" the same (a missing package has no signer). Fix commit `183ee884` (`BridgeLink.present()`; the drop path now reports NOT_INSTALLED and logs `nexus bridge removed`) with a new unit test `aBridgeUninstalledWhileBoundIsNotInstalledNeverNotTrusted`. All `com.rokid.context.phone.nexus.*` tests pass (BUILD SUCCESSFUL). The emulator still runs the old phone APK (not rebuilt), so the fixed text was not re-observed on screen.
7. **Logcat:** across the observed windows (cleared between phases, so not one continuous log) zero `FATAL EXCEPTION`, `ClassNotFoundException` or `SecurityException` from PCA, the bridge or the hub; the only `AndroidRuntime` lines were the test driver (`uiautomator`).

## Not verified here

Hub, PCA phone (Developer mode on, host back to Nexus then bridge removed) and PCA glasses app remain installed on the emulator; the emulator was stopped with `adb -s emulator-5554 emu kill`.
