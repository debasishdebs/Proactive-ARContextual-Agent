# Slice 3a M1 device run (Task 23b)

Controller runs `tools/m1-run.sh`. The phone is reached over Wi-Fi only (LAN API, plus wireless adb for the trace hand-over after the wear). The glasses are on USB only and are touched only by `pull` and `status`, AFTER the wear (`$G`). Nothing below prints the session token, the pairing code or a device secret.

## Your steps
1. Phone: Settings > Diagnostics > turn **Developer mode** on. Open the Canvas screen, turn **Use from a laptop** on (same Wi-Fi as the laptop). Read the **host:port**, the **pairing code** and the first 8 digits of the **certificate fingerprint**; the code lives 5 minutes (tap **New code** if it lapsed or locked).
2. Tell the controller: host:port, code, fingerprint. It runs `pair`, `plan` (must say `f5782e0d8610`, 0 problems), `shadow` (SHADOW only), then `collect start 25`.
3. Wear the glasses 20-30 minutes and go about normally (walk, sit, look at things). Keep the phone on the same Wi-Fi, screen can be off, Developer mode stays on.
4. Take the glasses off and put them on charge. Tell the controller; it runs `collect stop`, then `pull`.
5. Leave both apps alone while the controller runs `replay <traceId>` (about a minute). Do not tap Delete all or turn Developer mode off meanwhile.
6. Afterwards: Canvas LAN switch off. (Back-up of both apps and the install were done by the controller before step 1.)

## Controller sequence
```
tools/m1-run.sh pair <host:port> <code> <fp8>
tools/m1-run.sh plan && tools/m1-run.sh shadow && tools/m1-run.sh status   # plan=f5782e0d planMode=SHADOW in the heartbeat = EFFECTIVE
tools/m1-run.sh collect start 25
# ... worn ...
tools/m1-run.sh collect stop && tools/m1-run.sh pull ~/m1-pull && tools/m1-run.sh status
tools/m1-run.sh replay                           # the trace `pull` imported (or `replay <traceId>`)
```
Notes: the phone has no plan-ack route, so EFFECTIVE is read from the glasses heartbeat (`plan=`, `gen=`, `planMode=`, `planRevert=`, `shOpen=`, `shSkip=` in `files/capture_diag.log`); only heartbeat lines are read, never AssistServer or system logs. Automatic glasses-to-phone transfer is not built (later), so `pull` is the hand-over: it pulls the sealed trace with `trace-pull.sh` (glasses on USB), then for each trace `adb push`es it to the phone's staging dir `/sdcard/Android/data/com.rokid.context/files/trace-staging/<traceId>/` (the app's own external files dir: adb's shell user can write it on Android 14/15 without root; unverified here, no device access in this task) and calls `POST /api/traces/import` (Developer mode on; checksums, deletion epoch, tombstones and the 500 MB cap are enforced by the phone; the staging copy is deleted on success). The phone is selected by adb transport id (auto when it is the only other device in `adb devices -l`, else `M1_PHONE_TID=<id>`), never by serial (the wireless serial has spaces). A PARTIAL trace is refused (409) unless `pull <dir> --allow-partial`; it is then replayable but never publish evidence. `pull` also saves the heartbeat lines. `shOpen` is summed over the SHADOW heartbeats of the run (the whole log if you did several runs: use a fresh log or `--diag` on a trimmed file). `windows compared` = base passed + base failed.

## Pass criteria (all must hold)
- `plan`: `configHash=f5782e0d8610 problems=0 warnings=0`.
- `shadow`: `mode=SHADOW sent=True`; heartbeat shows `plan=f5782e0d planMode=SHADOW`, `planRevert=none`.
- The trace is `COMPLETE` and `exact=True` in `status`/`pull`, covering the worn run.
- `replay`: `jobState=DONE`, the failing-window share (`base_fail` / `windows_compared`, where `windows_compared` = base_pass + base_fail, inexact windows excluded) at most T percent with `windows_compared > 0` (T defaults to 3; `--max-fail-pct T` or `M1_MAX_FAIL_PCT`; HARD CAP 5: a larger or non-numeric value is refused before any replay; the line `failing_windows=.. total_windows=.. share=.. T=..` is printed, then the failures by kind when the report carries `baseFailKinds`, else `unclassified (N)`, informational), BatteryLine hours printed. The old rule was zero failing windows; `--legacy-total` is unchanged otherwise. Inexact windows are excluded from pass/fail but BOUNDED, never just dropped: the `inexact_bounds` line gives the reasons (`STALL`: the first decision after a sensor delivery stall met its recorded open of the same cause later than the 1300 ms slack (up to 2600 ms) and NOTHING else in the window disagreed; any other extra, miss or gate difference in a stall window is a plain failure; `ASYNC_CALLBACK`: a dwell/onset open without a replay twin; `CAPTURE_NOW`, `BIND_FAILURE`), the minutes and share of the span they cover and the delivery stalls of the trace (count, seconds, share); the `opens_range` line gives the opens as `[low, high]` (low = replayed opens in the exact windows + recorded opens in the inexact ones, high = low + replayed opens in the inexact ones; the range covers the excluded windows only and assumes every other window passed, so it is NOT a bound while `base_fail > 0`). Report both lines with the verdict; a run whose inexact share is large (the Task 23b diagnosis asked for >= 70 % exact minutes) is weak evidence whatever the verdict says.
- `replay`: `PASS shadow shOpen=... vs counterfactual glance_admissions=...`: the shadow `shOpen` total (SHADOW heartbeats of plan `f5782e0d` stamped inside the trace's interval: `m1-run.sh replay` filters them by the replay job's `fromMs`/`toMs`, read as wall-clock ms, and the heartbeat time in this machine's zone; without an interval the log is counted whole and the script says `UNFILTERED`, then use `--diag` with a log trimmed to the run) within `max(5 %, 4 opens)` of the counterfactual's GLANCE ADMISSIONS. The shadow counts the glances the admission test would have opened (a dwell glance, whatever the camera is doing, no timer opens, assuming each becomes a keep); timer opens and the total `opens` are NOT compared with it. The same line prints, as `INFO`, the counterfactual DWELL+ONSET opens (the admissions that also became a camera open, always <= the admissions): on the worn trace bc1f4b0e shOpen 82 vs 85 admissions vs 72 DWELL+ONSET opens.
- Old criterion (shadow total within +-5 % of ALL counterfactual `opens`): valid only for the SETTLE-wake scripted traces (GoldenScripts, `TraceParityTest`), where the scripts have no timer opens in the glance windows; on a worn walking trace it compares glance admissions with timer + dwell opens and fails by construction. `tools/m1-run.sh replay <id> --legacy-total` still prints it.
- No `planRevert` other than `none`, no phone or glasses crash.

## Hand-over tool (LGC10-min): `tools/handover.sh <out-dir>`
Read-only pull of the glasses traces and logs (own files via `run-as`, never the glasses logcat), the phone logs (`pca.log{,.1}`, `qna_eval.jsonl{,.1}`; a missing rotation is skipped with a count; refused `run-as` prints "phone logs not pulled: run-as refused (build not debuggable)" and exits 0) and the watch logcat only when `WATCH_TAGS` is set. It never installs, launches or stops an app. With glasses + phone + watch attached `M1_PHONE_TID` and `M1_WATCH_TID` (or `--phone-tid`/`--watch-tid`) are REQUIRED. It REFUSES everything while `files/trace_cleanup_pending` exists (or cannot be read) on the glasses, and computes the WEAR WINDOW from the glasses heartbeat lines (`chg=`; glasses clock): from the last unplug (last `chg=false` heartbeat after a `chg=true` one; with no earlier `chg=true`, the first heartbeat) to the first later `chg=true` heartbeat or the last heartbeat. No heartbeat in the window (none at all, or every heartbeat `chg=true`) is rejected as `NO HEARTBEAT EVIDENCE` (`--allow-no-heartbeat` labels and continues). Only traces whose manifest `endWallMs` is at or after the window start are kept (unreadable time = included, counted as `untimed`), logs are cut to lines at or after the window start (deny filter still applies); it prints the window start/end and the counts. After a seen unplug-then-plug-in it also writes the unplug time (host clock, ISO) to `~/.pca-helper/glasses-usb-last` (`$PCA_HELPER_HOME`), informational only. `M1_HB_MAX_AGE_MIN` is deprecated and ignored. Import: `--host HOST:PORT --code CODE --fp FP8` (or prompts in a terminal; pairing state lives in a temp dir removed on exit); `--no-import` or no pairing = files only, exit 0. After each successful import it writes the zero-byte marker `files/imu/transferred/<traceId>` on the glasses, outside the trace dir. `battery-run.sh summary` and `m1-run.sh pull` reject (label) runs with no heartbeat evidence (`ALLOW_NO_HEARTBEAT=1`, `M1_ALLOW_NO_HEARTBEAT=1`). Test: `tools/test-handover.sh` (fake adb, no device).
