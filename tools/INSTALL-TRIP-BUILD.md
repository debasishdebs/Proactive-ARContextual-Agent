# tools/install-trip-build.sh

Safe, dry-run-by-default installer for the trip build. Procedure source: `docs/superpowers/plans/handoffs/v17-upgrade-recovery.md`. Still needs the user's explicit go.

```
# 1. Dry run (default): read-only checks, prints every step. Writes NOTHING (no temp dir, no file on the host, nothing on the phone) and pulls NOTHING
tools/install-trip-build.sh --phone <serial> --glasses <serial> [--watch <serial>] --apks ~/Desktop/rokid/backups/apks-v110-<sha>
# 2. Real run (only after the user says go): add --go [--tag pre-v17-20261121]
```

Serials are mandatory (no auto-detect, every adb call uses `-s`). Refused: equal serials, serial not in `adb devices`, watch serial equal to phone/glasses, emulator serial with `--go` (needs `--allow-emulator`), missing APK, wrong package, downgrade (`--allow-downgrade` exists, do not use), signing cert differs from the installed one, a call active. The script FAILS CLOSED: any uncertainty refuses. Exit codes: 0 = success, 2 = REFUSED (a guard or an uncertainty stopped it), 3 = an installed app is NOT verified (UNVERIFIED) or its log scan FAILED (never a success). For the phone the glasses step is NOT run ("glasses NOT installed"); for the glasses the message says "glasses installed but verification FAILED" (the glasses WERE installed; the watch step is not run). Inspect logcat ( inspect logcat, do NOT restore from the backup unless the app fails to open its data), any other nonzero = failure (for example an install or a verification step failed).

- Signature: `apksigner` missing, installed-APK pull failing or an unreadable certificate all REFUSE. Only override: `--accept-unverified-signature` (printed prominently); with `--go` on a non-emulator it additionally needs `--i-understand-no-signature-check`. A certificate mismatch is never overridable. The dry run does not pull the installed APK: it prints "signature check will run with --go".
- Call guard: `dumpsys telephony.registry` must succeed and EVERY `mCallState=<n>` line must be exactly `mCallState=0` (anchored); none, junk, differing values or an adb failure refuse. Re-checked before the backup and every install.
- Backup: `am force-stop` must succeed, then `pidof` must prove the process is gone (exit 1 and empty output; any adb/transport error refuses; a few retries). SHA-256 digests are checked (64 hex) and every metadata/APK write is checked. Disk preflight: free space in the backup dir and temp dir must be at least 3x the app data size (`run-as du`). The tar, the previous APK and the metadata are `0600`.
- Failure messages track the phase (`preflight|backup|installing|installed`). Before the install step starts it says "No change was made to the phone: leave phone data untouched" and that any backup is unvalidated (do not restore from it). Restore steps are printed only after a validated backup AND the install started; they are non-destructive first (quarantine copy before anything is replaced).

- Serial aliases (device identity): one physical device can appear under several adb serials (USB serial, wireless `adb-<serial>-<suffix>._adb-tls-connect._tcp`, `ip:port`), so comparing serial strings is not enough. `watch-debug.apk` has the SAME applicationId (`com.rokid.context`) as the phone app, so installed on the phone's alias it would REPLACE the phone app. Every supplied serial (phone, glasses, optional watch) is resolved through adb queries on that serial to an identity: hardware serial (`ro.serialno`, fallback `ro.boot.serialno`) + `settings get secure android_id` + `ro.product.model` + `ro.build.fingerprint`. Any missing, empty or placeholder value (unknown, null, zeros) REFUSES. All identities must be pairwise different (equal hardware serial, equal android_id or equal identity = alias): the refusal names the two serials. The identities are re-resolved and compared again (and against the preflight result) immediately before EVERY install step, so a changed identity refuses. The watch target must also report a watch (`ro.build.characteristics` contains `watch` or `pm list features` has `android.hardware.type.watch`) and, by the pairwise rule, not be the phone; `watch-debug.apk` is installed ONLY to `--watch`. Endpoint-style serials (containing `:` or `_adb-tls`) print a notice. Prefer ONE serial per physical device.

Order: backup (force-stop proven only by a single well-formed `__PCA_RC` marker with pidof status 1 and an empty pid list, any other state refuses; `run-as tar c .`, validated: `tar -t`, db and `db_key.xml` listed, size, encrypted header, sha256; old phone APK kept beside it) in `~/Desktop/rokid/backups/pca-phone-pre-<tag>.tar` -> `install -r` phone -> 60 s log scan (logcat is NOT cleared, other logs are kept; before each install a best-effort `logcat -G 16M` and the device epoch `adb shell date +%s`, validated numeric, are taken; counts only; logcat retrieval is checked separately from counting, and empty/failed logs end as INSTALL DONE BUT NOT VERIFIED, exit 3, with manual check commands, never as success) -> glasses -> optional watch. The scan is three-valued. The app pid is sampled BEFORE the 60 s window and AFTER ONE `logcat -d -b all -v threadtime -v epoch` snapshot; everything is filtered from that single capture (by pid, plus lines naming the package). Missing pid at either point, a changed pid, several pids (pidof, or process start/death/crash lines in the snapshot) or an app not running at the end = FAIL "app restarted during the 60 s window" (never CLEAN). Each log line is classified on its own: ANY real signature makes it a FAIL line and the allow-list can never subtract it (`E sqlcipher_mlock errno=12 SQLiteException: file is not a database` = FAIL). Signatures (case-sensitive): `FATAL EXCEPTION`, `Process: <pkg>`, any `SQLiteException` (android.database.sqlite / net.sqlcipher.database / net.zetetic.database.sqlcipher / unqualified), `SQLiteDatabaseCorruptException`, `SQLiteDiskIOException`, `SQLiteFullException`, `file is not a database`, `SQLITE_NOTADB`, `Migration didn't properly handle`, `A migration from N to M was required but not found`, `Room cannot verify the data integrity`, `no such column`, `no such table`, `duplicate column`, `IllegalStateException` mentioning Room/openHelper/database, `Cannot open database`, `Unable to open database`, `database disk image is malformed`, `ANR in <pkg>`, `Application Not Responding`. Updated rules: SQLite signature is any `SQLite[A-Za-z]*Exception` (CantOpenDatabase, Constraint, DiskIO, Full, Misuse, ...) plus `SQLITE_CANTOPEN`, `Could not open database`, `code 14`. Package matching uses a real boundary (`(^|[^A-Za-z0-9_.])pkg([^A-Za-z0-9_.]|$)`): lines of the app pid need only a signature; lines of other pids (system_server etc.) need the package boundary AND a signature, and ANR counts only with the package as the SUBJECT (`ANR in <pkg>`, `Application Not Responding: <pkg>`), never `waiting on <pkg>` or `com.pkg.other`. Only lines from install start - 2 s onward are scanned. UNVERIFIED (exit 3) reasons: logcat retrieval failed, short/empty log, no app-pid lines, install start time unknown, no parseable timestamp, or the oldest retained line is newer than install start - 2 s (buffer wrap: "log buffer does not cover the install window: check logcat manually / increase the buffer with logcat -G 16M before the install"). CLEAN = none; BENIGN-ONLY = only lines that match the allow-list (`sqlcipher_mlock`, `Long monitor contention`) AND no signature, printed as a note, still success; FAIL = any signature or restart (exit 3). The bare words SQLCipher/Room are not errors. Stops at the first failure and prints the rollback. `watch-debug.apk` (same applicationId as the phone app) only ever goes to `--watch`.

Rollback: restore from the validated tar, never uninstall or `pm clear` (section 4 of the recovery doc; the script prints it with your paths).

Self-test (emulator only, throwaway data): `--self-test --phone emulator-5554 --apks <dir> [--go] [--allow-plaintext-db]`; `PCA_SELFTEST_CALLSTATE=2` simulates a call. `--self-test`, `--allow-plaintext-db` and `PCA_SELFTEST_CALLSTATE` are hard-refused on any non-`emulator-*` serial (the emulator debug build is unencrypted). `--self-test` first runs the refusal fixtures; `--fixtures` runs only those (function-level overrides, no adb, no device): call guard, force-stop/pidof, SHA-256, disk, signature, argument rules, device identity/alias/watch checks.

Cannot verify: real Keystore survival, the glasses/watch launch screens, UI state after install (do the manual checks of section 3), and a signature without the explicit override flag (it refuses).
