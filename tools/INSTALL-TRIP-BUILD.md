# tools/install-trip-build.sh

Safe, dry-run-by-default installer for the trip build. Procedure source: `docs/superpowers/plans/handoffs/v17-upgrade-recovery.md`. Still needs the user's explicit go.

```
# 1. Dry run (default): read-only checks, prints every step. Writes NOTHING (no temp dir, no file on the host, nothing on the phone) and pulls NOTHING
tools/install-trip-build.sh --phone <serial> --glasses <serial> [--watch <serial>] --apks ~/Desktop/rokid/backups/apks-v110-<sha>
# 2. Real run (only after the user says go): add --go [--tag pre-v17-20261121]
```

Staged builds (2026-11-20; installed: 18c1b76a): `~/Desktop/rokid/backups/apks-v110-cand-4436d1a5` (conservative trip candidate) and `~/Desktop/rokid/backups/apks-v110-train-166d3fd4` (full train: adds data saver and Model privacy). Same procedure for both: dry run, then `--go --tag <tag>` only on the user's go; the helper takes the validated backup before installing the phone, then the glasses. Device needed for every step; new-feature tests: `docs/superpowers/plans/handoffs/device-session-runbook-2026-11-19.md` section 13.

Serials are mandatory (no auto-detect, every adb call uses `-s`). Refused: equal serials, serial not in `adb devices`, watch serial equal to phone/glasses, emulator serial with `--go` (needs `--allow-emulator`), missing APK, wrong package, downgrade (`--allow-downgrade` exists, do not use), signing cert differs from the installed one, a call active. The script FAILS CLOSED: any uncertainty refuses. Exit codes: 0 = success, 2 = REFUSED (a guard or an uncertainty stopped it), 3 = an installed app is NOT verified (UNVERIFIED) or its log scan FAILED (never a success). For the phone the glasses step is NOT run ("glasses NOT installed"); for the glasses the message says "glasses installed but verification FAILED" (the glasses WERE installed; the watch step is not run). Inspect logcat ( inspect logcat, do NOT restore from the backup unless the app fails to open its data), any other nonzero = failure (for example an install or a verification step failed).

- Form factor (before ANY install, dry run included): the watch and phone APKs share applicationId `com.rokid.context`, so a watch build staged as `phone-debug.apk` would pass the package and signature checks and replace the phone app. Each APK is inspected with the newest build-tools `aapt2`/`aapt` (`dump badging` and `dump xmltree AndroidManifest.xml`). REFUSED (exit 2): the phone APK declares `uses-feature android.hardware.type.watch`, contains watch-only components (`com.rokid.context.watch`, `MotionPassiveService`, `MotionReceiver`, `wearable.standalone`) or its launchable activity is not `com.rokid.context.MainActivity`; the glasses APK declares watch or its launchable activity is not `com.rokid.context.glasses.MainActivity` (package must be `com.rokid.context.glasses`); the watch APK does not declare the watch feature or is not `com.rokid.context.watch.MainActivity`. No aapt/aapt2 or a failed dump also REFUSES. Only override: `--accept-unverified-form-factor` (printed prominently; it never excuses a verified mismatch).
- Signature: `apksigner` missing, installed-APK pull failing or an unreadable certificate all REFUSE. Only override: `--accept-unverified-signature` (printed prominently); with `--go` on a non-emulator it additionally needs `--i-understand-no-signature-check`. A certificate mismatch is never overridable. The dry run does not pull the installed APK: it prints "signature check will run with --go".
- Call guard: `dumpsys telephony.registry` must succeed and EVERY `mCallState=<n>` line must be exactly `mCallState=0` (anchored); none, junk, differing values or an adb failure refuse. Re-checked before the backup and every install.
- Backup: `am force-stop` must succeed, then `pidof` must prove the process is gone (exit 1 and empty output; any adb/transport error refuses; a few retries). SHA-256 digests are checked (64 hex) and every metadata/APK write is checked. Disk preflight: free space in the backup dir and temp dir must be at least 3x the app data size (`run-as du`). The tar, the previous APK and the metadata are `0600`.
- Failure messages track the phase (`preflight|backup|installing|installed`). Before the install step starts it says "No change was made to the phone: leave phone data untouched" and that any backup is unvalidated (do not restore from it). Restore steps are printed only after a validated backup AND the install started; they are non-destructive first (quarantine copy before anything is replaced).

- Serial aliases (device identity): one physical device can appear under several adb serials (USB serial, wireless `adb-<serial>-<suffix>._adb-tls-connect._tcp`, `ip:port`), so comparing serial strings is not enough. `watch-debug.apk` has the SAME applicationId (`com.rokid.context`) as the phone app, so installed on the phone's alias it would REPLACE the phone app. Every supplied serial (phone, glasses, optional watch) is resolved through adb queries on that serial to an identity: hardware serial (`ro.serialno`, fallback `ro.boot.serialno`) + `settings get secure android_id` + `ro.product.model` + `ro.build.fingerprint`. Any missing, empty or placeholder value (unknown, null, zeros) REFUSES. All identities must be pairwise different (equal hardware serial, equal android_id or equal identity = alias): the refusal names the two serials. The identities are re-resolved and compared again (and against the preflight result) immediately before EVERY install step, so a changed identity refuses. The watch target must also report a watch (`ro.build.characteristics` contains `watch` or `pm list features` has `android.hardware.type.watch`) and, by the pairwise rule, not be the phone; `watch-debug.apk` is installed ONLY to `--watch`. Endpoint-style serials (containing `:` or `_adb-tls`) print a notice. Prefer ONE serial per physical device.

Order: backup (force-stop proven only by a single well-formed `__PCA_RC` marker with pidof status 1 and an empty pid list, any other state refuses; `run-as tar c .`, validated: `tar -t`, db and `db_key.xml` listed, size, encrypted header, sha256; old phone APK kept beside it) in `~/Desktop/rokid/backups/pca-phone-pre-<tag>.tar` -> `install -r` phone -> 60 s log scan (logcat is NOT cleared, other logs are kept; before each install a best-effort `logcat -G 16M` and the device epoch `adb shell date +%s`, validated numeric, are taken; counts only; logcat retrieval is checked separately from counting, and empty/failed logs end as INSTALL DONE BUT NOT VERIFIED, exit 3, with manual check commands, never as success) -> glasses -> optional watch. The scan is three-valued. The app pid is sampled BEFORE the 60 s window and AFTER one `logcat -d -b <buffer> -v threadtime -v epoch` snapshot per relevant buffer (`main`, `system`, `crash`, all taken in the same step); everything is filtered from those captures (a genuinely unprefixed continuation line inherits the previous record's timestamp/pid, so a stack line naming a signature still FAILs) (by pid, plus lines naming the package). Missing pid at either point, a changed pid, several pids (pidof, or process start/death/crash lines in the snapshot) or an app not running at the end = FAIL "app restarted during the 60 s window" (never CLEAN). Each log line is classified on its own: ANY real signature makes it a FAIL line and the allow-list can never subtract it (`E sqlcipher_mlock errno=12 SQLiteException: file is not a database` = FAIL). Signatures (case-sensitive): `FATAL EXCEPTION`, `Process: <pkg>`, any `SQLiteException` (android.database.sqlite / net.sqlcipher.database / net.zetetic.database.sqlcipher / unqualified), `SQLiteDatabaseCorruptException`, `SQLiteDiskIOException`, `SQLiteFullException`, `file is not a database`, `SQLITE_NOTADB`, `Migration didn't properly handle`, `A migration from N to M was required but not found`, `Room cannot verify the data integrity`, `no such column`, `no such table`, `duplicate column`, `IllegalStateException` mentioning Room/openHelper/database, `Cannot open database`, `Unable to open database`, `database disk image is malformed`, `ANR in <pkg>`, `Application Not Responding`. Updated rules: SQLite signature is any `SQLite[A-Za-z]*Exception` (CantOpenDatabase, Constraint, DiskIO, Full, Misuse, ...) plus `SQLITE_CANTOPEN`, `Could not open database`, `code 14`. Package matching uses a real boundary (`(^|[^A-Za-z0-9_.])pkg([^A-Za-z0-9_.]|$)`): lines of the app pid need only a signature; lines of other pids (system_server etc.) need the package boundary AND a signature, and ANR counts only with the package as the SUBJECT (`ANR in <pkg>`, `Application Not Responding: <pkg>`), never `waiting on <pkg>` or `com.pkg.other`. Only lines from install start - 2 s onward are scanned. UNVERIFIED (exit 3) reasons: logcat retrieval failed, short/empty log, no app-pid lines, install start time unknown, a buffer cannot be read, or a buffer does not cover the install window ("log buffer <name> does not cover the install window"). Coverage is proven PER BUFFER with the FIFO rule, because Android prunes each buffer on its own and oldest-first (`logcat -g` "consumed" is only the memory currently held, not cumulative writes, so it is never used): (1) a buffer with ZERO records is covered (anything logged after install start would still be there, and then the buffer would not be empty); (2) a non-empty buffer is covered only if its own oldest retained record is <= install start - 3 s (floored), since if an older-than-start record survived nothing newer was pruned; (3) otherwise (oldest record newer, or unparseable timestamp) = UNVERIFIED exit 3 "log buffer <name> does not cover the install window": the device keeps too little log history for the install window: close noisy apps, do the manual post-install checks (`docs/superpowers/plans/handoffs/v17-upgrade-recovery.md` section 3 / trip-install-checklist section 4), optionally start a continuous capture BEFORE installing (`adb -s <serial> logcat -b all -v threadtime -v epoch > ~/Desktop/rokid/backups/logcat-<tag>.txt`), then re-run; the glasses step is NOT executed. An old line in a quiet buffer never proves coverage for another one. CLEAN = none; BENIGN-ONLY = only lines that match the allow-list (`sqlcipher_mlock`, `Long monitor contention`) AND no signature, printed as a note, still success; FAIL = any signature or restart (exit 3). The bare words SQLCipher/Room are not errors. Stops at the first failure and prints the rollback. `watch-debug.apk` (same applicationId as the phone app) only ever goes to `--watch`.

Rollback: restore from the validated tar, never uninstall or `pm clear` (section 4 of the recovery doc; the script prints it with your paths).

Self-test (emulator only, throwaway data): `--self-test --phone emulator-5554 --apks <dir> [--go] [--allow-plaintext-db]`; `PCA_SELFTEST_CALLSTATE=2` simulates a call. `--self-test`, `--allow-plaintext-db` and `PCA_SELFTEST_CALLSTATE` are hard-refused on any non-`emulator-*` serial (the emulator debug build is unencrypted). `--self-test` first runs the refusal fixtures; `--fixtures` runs only those (function-level overrides, no adb, no device): call guard, force-stop/pidof, SHA-256, disk, signature, argument rules, device identity/alias/watch checks, APK form-factor refusals (247 fixtures in total).

Cannot verify: real Keystore survival, the glasses/watch launch screens, UI state after install (do the manual checks of section 3), and a signature without the explicit override flag (it refuses).

Real-logcat validation (2026-11-18, Android 14 emulator): the `-v threadtime -v epoch` layout is `<spaces><epoch.mmm> <pid> <tid> <level> <tag>: <msg>` (pid = awk field 2, epoch = field 1); `--------- beginning of <buf>` separators have no timestamp and are ignored; a multi-line message or stack trace is emitted as one full record per line (each with its own header), so pid filtering works on continuation lines. The phone launch uses `am start -W` so the pid exists before it is sampled (without `-W` the first sampling raced the process start and gave a false FAIL "no pid before the window"). See docs/superpowers/reviews/2026-11/install-script-real-logcat-2026-11-18.md.

Extra UNVERIFIED (exit 3) rules, evaluated after the FAIL check (a real signature still wins): (a) chatty summaries: a `chatty ... identical N lines` or `expire` line from the app pid, or naming the app package at a boundary, means logd collapsed or pruned app lines ("logd collapsed or pruned app lines during the window: verify manually"); a chatty line for another package is ignored. (b) Clock continuity: `date +%s` and `/proc/uptime` are read on the device before the install and after the snapshots; if the wall-clock delta and the uptime delta differ by more than 5 s, or any of the four values is unreadable, the result is "device clock changed during the window".

## What the scan cannot prove

- Selective chatty pruning: logd can prune records of noisy UIDs while older records of others survive, so "oldest retained record is old enough" is a FIFO assumption, not a proof for every UID.
- External clears: another actor clearing a buffer (or one UID's records) during the window leaves an empty or short buffer that looks covered.
- FIFO assumption: coverage reasoning assumes oldest-first pruning per buffer; serialized/chatty buffers can deviate.
- Small clock changes (under 5 s) and a clock rolled back and forward again are not detected.

The manual post-install checks (v17-upgrade-recovery.md section 3) therefore remain MANDATORY even after CLEAN.

## Post-install check

`tools/post-install-check.sh --phone <serial> [--glasses <serial>] --apks <folder>` (and `--fixtures`, no device). READ-ONLY: every adb call goes through an allow-list (`adb_safe`, fixture-tested) that refuses install, uninstall, clear, force-stop, grant, settings put, input, `logcat -c` and any redirect; it only reads dumpsys/getprop/logcat -d, `cat`s two prefs files via run-as, and copies the installed base APK into a temp dir it removes. Prints counts, hashes and names only, never a log line.

Each check prints PASS / WARN / FAIL / UNKNOWN with a reason; exit 0 = no FAIL, 1 = any FAIL, 2 = refused/usage.

1. Identity: phone and glasses are distinct physical devices, phone is not a watch.
2. Version and sha256 of the installed base APK vs the staged APK (PASS only on exact match), signature digest (needs aapt/apkanalyzer and apksigner, else UNKNOWN).
3. Every runtime permission granted (from `dumpsys package`); POST_NOTIFICATIONS, BLUETOOTH_CONNECT, location reported; battery-optimization exemption (WARN if missing).
4. Process running, same pid 10 s apart (`PCA_CHECK_PIDWAIT` overrides the wait).
5. Logcat counts of FATAL EXCEPTION / ANR / SQLite-Room migration errors for the app pid and package (same signatures as the install script).
6. Safety defaults OFF: `pc_dev` forget_v2, multilingual_ask; `proactive_settings` deliver_phone, deliver_hud, deliver_nexus. Debuggable builds only (run-as); otherwise UNKNOWN.
7. Call state, clock skew (WARN above 120 s), airplane/Bluetooth/Wi-Fi, battery (WARN below 50%), free storage (WARN below 2 GB).
8. Glasses: installed, version/sha, process. Link state is not observable read-only: always UNKNOWN, confirm on the phone.

9. Trip-build checks (phone, debuggable builds via `run-as`; otherwise one UNKNOWN; counts and enums only, never a log line, name or id; fixtures 176 total with `--fixtures`; a failed or truncated log segment read makes every log-derived check UNKNOWN, never PASS):
   - `log segments`: `files/logs` has `pca.log` (+ `pca.log.N`), total under 300 MB (FAIL at or above; WARN if `pca.log` is missing).
   - `detailed log`: inferred from the logs (the app-start milestone is always written, the hourly `PcDiag heartbeat` only while Detailed log is on): heartbeat within 70 min = ON; none after more than 70 min of running = OFF; shorter run = UNKNOWN; stale heartbeat = WARN.
   - `log forbidden shapes` (last `pca.log`): lines with a coordinate-like decimal pair or `http` = FAIL, `@` only = WARN; counts only.
   - `data saver (PcData)`: `blocked` lines by fixed reason token (anything outside the DataPolicy list prints as `other`) and the last `net cost=` enum.
   - `prefs files`: presence by exact name only of `place_pins`, `data_saver`, `ai_backend`, `ai_backend_init`, `online_map` (the last is optional). Whether they are excluded from the backup rules is NOT checked here (that needs the APK manifest; see the BackupRulesTest).
   - `model privacy`: `mode=AUTO|OFFLINE_ONLY|missing|garbled`, `reset=yes` (WARN) when the sentinel says the stored choice was lost (same rule as `ModelPrivacyStore`).
   - `place attempts`: count of `place attempt` lines in the last 24 h (`PCA_CHECK_PLACE_HOURS`, measured back from the last log record) by outcome; unknown outcome tokens count as garbled (WARN). Own parser, not `tools/place-attempt-report.sh` (that prints ids).
   - `pins`: total, with a Moment link, without one (python3 on the Mac; never prints a name or id).
   - `db version` / `db integrity`: a host COPY of `context.db`, only when the header and the app's own `db_encrypted` flag both say plaintext (same pairing rule as the install script) and `sqlite3` exists: `user_version` must be 18 and `integrity_check` ok; also `db rows moment_location`, `db rows place_card_log` and `db rows scene_centroid` and `db rows model_attribution` (row counts only, UNKNOWN if unreadable). v18 cannot be downgraded: the rollback is `v17-upgrade-recovery.md` section 4 (restore the pre-install backup). Encrypted (the normal case) = UNKNOWN, inconsistent = WARN.
   Not verifiable without a device: the real `ls -l` / prefs / log formats on a phone (parsers follow the source and the emulator-style samples), the 70-minute heartbeat on a real run, and everything on a non-debuggable build.

Emulator run (phone only, 1.0.0 code 4 candidate): 20 PASS, 1 WARN (no battery exemption on the emulator), 0 FAIL; a wrong APK folder gave FAIL on sha256 and a deliver_hud flag set ON gave FAIL on safety defaults (both exit 1).

## Link health report (read-only)
`tools/link-health-report.sh --phone <phone serial> [--date MM-DD]` reads PCA's own log from the phone (debuggable build, `run-as`) and prints, per clock hour: glasses frames received, link CONNECTING/CONNECTED, authorization timeouts, SESSION_TERMINATED send failures, watchdog HubDown ticks, relaunch lines and the longest quiet gap between frames. Counts and hours only; nothing is written to the device. `--file <pca.log>` reads saved logs without adb; `--fixtures` runs its 6 parsing cases. Reads every `pca.log` segment (the trip build keeps up to 60 x 5 MB).

## Place attempt report (read-only)
`tools/place-attempt-report.sh --phone <phone serial> [--date MM-DD | --since "MM-DD HH:MM" [--until ...]] [--pin-map <file>]` parses the content-free `place attempt` and `pack lookup` lines (debuggable build, `run-as`), oldest segment first, and prints counts, fixed tokens, validated ids and numbers only, never a log line. `--file <oldest> ...` reads saved logs; `--fixtures` runs its parsing cases. `--pin-map` labels ids on the laptop only. The ids form a place-level trail (PRIVACY.md section 8): keep the output private.

Purpose of the link report: measure whether the shared glasses link is stable (for example when Rokid-Coder is also active) before designing any arbitration. Example (2026-11-19 outing): 387 frames, 2-3 reconnects per hour in the busy hours, each recovered; the 20 authorization timeouts were all in idle (unworn) hours.
