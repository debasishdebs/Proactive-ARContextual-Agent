## Built
1. **Windows in the shared catalogue (C1b).** `WindowRing` (core:model `context/graph`): Int32 one-second ring (milli-units, `quantise` = `Math.round(x*1000)` clamped to +-2e6), exact Long running sum, monotonic deque of slot indexes for max, 1 to 300 s. FULL-HORIZON: it answers only when every slot of the horizon holds a valid value; warming and any gap answer UNAVAILABLE, never a partial value and never a zero. `mean = (sum/n)/1000`, `frac = sum/n` over 0/1 slots, `max = max/1000`.
2. **Window terms in programs (X6).** New lowered op `{op:win, name, agg:max|mean|frac, sec:1..300[, t]}` over the seven one-second features only (never `ctx`/`ctxAgeS`); `frac` counts the seconds whose quantised value is above `t`. A TERM is the distinct (signal, aggregate, seconds[, threshold]); at most 4 per plan over ALL programs; a term used twice shares one ring. Ring bytes (`4*sec`, `8*sec` for max) are added to the plan bytes against the 8192 cap, in `PlanCompiler` (`EXPR_BYTES`) and in `PlanValidator` on the glasses. `ExprSignals` now keeps the last 300 s of quantised slots (missing seconds are INVALID slots); every `ExprRunner` reads them into ITS OWN rings: bound empty at the plan apply (`bind`), read at the 1 Hz tick (`tick`, from the existing CaptureService 1 s loop) and at every evaluation, reset at capture session restart (`ExprSignals.reset()` in `startSmart`, epoch bump). A guard reading a window keeps the candidate while it warms (UNAVAILABLE keeps). `SignalCatalog.toJson()` lists the window ops (`windows` block).
3. **Replay parity.** `CaptureSimulator` binds the candidate's runner to its fresh `ExprSignals` at the start (empty rings, exactly like a plan apply; no ring snapshot in the trace) and ticks the value programs once a second of event time. `ReplayResult.windowWarmingS` / `warming` mark a replay whose first seconds are warming (a trace recorded while the plan was already running had full windows on the device), `valueTicks` counts overrides per value program.
4. **`expr.value` programs.** New node type `expr.value` ("Value (expression)", RT_GLASSES, `liveable=false`, params `graph`, `row` in REST|VEHICLE_PASSENGER|VEHICLE_DRIVING|FLIGHT, `field` in capPerMin|settledGapS|quietGapS|walkGapS|stillCapGapS). Lowers to `{id, role:"value", row, field, out, s}`. ONE field of ONE editable row per program, one program per target; WALKING/UNKNOWN cannot be named (param enum, `EXPR_VALUE_TARGET` in the lowering, `policy row X is locked` in the glasses validator); no other field exists (not pause, nudges, forceSettle, the reserved timer, the veto). The number is clamped in `ExprValues` to the row's own bounds (cap `PlanBounds.CAP_PER_MIN` 1..4 rounded, gaps `GAP_MIN_MS`..`GAP_MAX_MS` = 5..300 s; the program carries no bound of its own). Error or UNAVAILABLE (also a warming window) = no override = the plan row's own value. The row hook is `ExprRunner.tune(state, row)`, called from `ActiveConfig.policyFor` (glasses, so `profile`, `contextCap`, the session all see it) and from `CaptureSimulator.candRow`. Evaluated at most once a second (`GlanceGuard.tickValues` from the 1 s loop; replay: right after each second's features; a SHADOW config ticks inside `ShadowRunner.fired`, so it only changes what is counted). Value errors count in `errTotal` and therefore toward `auto:exprErr` (div0 still never does). SHADOW/TRIAL only (LIVE is refused in core for every plan).

## Decisions taken (please review)
1. **A window answers only when the WHOLE horizon is valid.** One missed second (the feed stalls 10-14 % of the time per the sensor-FIFO lead) makes a 300 s window UNAVAILABLE for up to 300 s; guards keep and values take the default meanwhile. Safe, but windows will be unavailable often on a stalling device; relaxing it to "at least N of M valid" is a spec change.
2. **Term identity includes the `frac` threshold** (the spec's triple has none); two `frac` terms with different thresholds are two terms.
3. **Window slots come from a shared per-second history in `ExprSignals`**, read by each runner (active and SHADOW have their own rings), so no 1 Hz callback registration is needed; the apply instant is "the first tick after the apply" (at most 1 s late) on the device and exactly the first event in replay.
4. **Window state per term is `4*sec` (`8*sec` for max) bytes**, e.g. three 300 s max windows (7200) do not fit next to a 1.6 KB plan; two max + one mean do. Four 300 s max windows are 9600 and always refused.
5. **Values: `gap` fields are in seconds** (like the canvas rate table), the cap is rounded to a whole number, a gap can never be 0 (inherit) from a value. The S68 rule still applies: a plan gap below the settings profile has no effect.
6. **`sigSchema 2`, not a new planSchema**, so scalar plans and hashes stay untouched; an old glasses build refuses with `bounds`, a build with the runner but no `sig2` with `unsupported:sig2`.
7. The row hook is in `ActiveConfig.policyFor` / `candRow` rather than inside `PlanResolver` (which only builds the static rows from the plan); both consumers of the resolver's rows call `ExprRunner.tune`.
