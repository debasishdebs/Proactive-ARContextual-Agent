- **Critical — Tasks 6–7: personal data would be exported and backed up.** `context_sources` already belongs to `SourceSettingsStore`, appears in `ConfigExport.PREFS_FILES`, and is explicitly restorable in `BackupRulesTest`. “Must not be added” changes nothing. **Fix:** reserve separate non-exported, backup-excluded storage for addresses/pins, or explicitly remove/filter the existing file and update both backup XMLs, device-transfer rules and tests. Preserve existing connector/nudge preferences.

- **Critical — Tasks 2, 4, 11: the walking guarantee is contradicted.** A `"SPEED"` reason disables the local walking veto. One erroneous or stale ≥25 km/h fix can therefore reduce capture while the wearer walks; the proposed test explicitly requires this. **Fix:** make local walking override every reducing context policy, and rewrite `fastSpeedLiftsTheVeto`. Any exception needs an explicit change to the binding requirement.

- **Critical — Tasks 7–9: intent work bypasses deletion fences.** An image loaded before Forget/Delete all can finish afterward, update surviving metadata and feed deleted activity into fusion. `MemoryWipe.generation` exists, but the sampler never checks it; `setIntent`’s affected-row count is ignored. **Fix:** fence admission and completion with generation, source-enabled state, pipeline state and tombstone checks; persist conditionally in a transaction and emit only after a successful update. Test deletion and disabling while classification is suspended.

- **Important — Tasks 4, 6–7: location FGS activation is incomplete.** The service enters foreground before `HubGraph` is built; changing `wantLocation` does not refresh its types. Vehicle suspicion commonly starts after backgrounding, when adding location is constrained by while-in-use permission rules. Existing fallback also drops microphone. **Fix:** define foreground activation/re-entry, actual `locationHeld` state, independent type fallback and deferred retry on resume; request fixes only while location access is valid. Test API 31/35 grant, background suspicion, refusal and sticky restart. [Android FGS requirements](https://developer.android.com/develop/background-work/services/fgs/service-types#location)

- **Important — Tasks 3, 10: manifest component names are wrong.** Namespace/application ID is `com.rokid.context`; classes are under `com.rokid.context.phone.context`. `.context.ActivityTransitionReceiver` and `.context.WatchMotionProvider` resolve elsewhere. **Fix:** use `.phone.context.…` or fully qualified names; test resolution through the merged manifest.

- **Important — Tasks 6, 11: disabling does not revoke context promptly.** Stopping adapters leaves fusion evidence, connected-car flags and hysteresis intact. All-off emits null, which `Hub` ignores; changing `applyToCapture` need not emit until the next heartbeat. **Fix:** clear evidence by source, reject late callbacks, recompute immediately and send an explicit UNKNOWN/`apply=false` revocation before going silent. Test disabling during DRIVING and shadow-mode changes without a state transition.

- **Important — Tasks 6–7: ownership and shutdown are unspecified.** Starting `ContextHub` in `HubGraph.build()` makes graph construction start sensing; `Hub.stop()` has no corresponding context shutdown. Separate `ContextSourceSettings.of()` instances also have independent change counters. **Fix:** specify one process-wide settings/hub instance, observe actual preference changes, and attach idempotent start/stop to service lifecycle. Test service stop/restart and writes through a second settings reference.

- **Important — Tasks 6, 9–10: the promised single-threaded fusion is not enforced.** Provider calls arrive on Binder threads; sampler completion and Android callbacks can call `accept()` concurrently. Watch sequence/rate checks can race too. **Fix:** serialize evidence/settings/ticks through one dispatcher or actor; make intake validation and sequence advancement atomic. Add concurrent-call tests. [Android Binder threading](https://developer.android.com/develop/background-work/services/aidl)

- **Important — Task 4: approximate-speed detection fails with normal updates.** Replacing the previous fix every 15–30 seconds prevents the five-minute baseline used by the test. With 2 km accuracy per fix, each comparison requires movement over 12 km. **Fix:** retain one baseline until displacement/time criteria pass, with bounded expiry and reset rules. Test a continuous sequence of intermediate fixes, rather than only two distant endpoints.

- **Important — Tasks 3–4: callback receipt is treated as observation time.** Delayed activity transitions and cached/batched location fixes become fresh evidence. Step callbacks likewise ignore sensor timestamps, potentially placing a batch in one bucket. **Fix:** translate elapsed observation timestamps into the fusion time domain, reject stale/out-of-order observations, and bucket steps by sensor time. Test delayed batches and wall-clock changes. [Activity transition timestamps](https://developers.google.com/android/reference/com/google/android/gms/location/ActivityTransitionEvent)

- **Important — Tasks 8–9: historical photos can control current capture.** `frame_meta.createdAt` is ingest time; the handoff documents buffered flight photos arriving later in a burst. The sampler labels these as current activity. **Fix:** distinguish receipt time from validated capture time; exclude backlog or uncertain-age frames from live fusion while allowing stored annotations. Test delayed flight photos arriving during a walk.

- **Important — Task 11: context caps are not hard caps.** `KeyframeGate` permits twice the cap for sufficiently different dwell frames; `hardCap` currently receives only `resting`. Thus vehicle cap 1 permits 2, and REST cap 2 permits 4. **Fix:** propagate a context hard-cap flag through dwell admission, `offer()` and `flushWindow()`; define the manual-capture exemption. Test large turns and highly different hashes.

- **Important — Tasks 6, 11: reconnect can discard the current context.** `onReady()` advances `sessionStartMs`, then resends a cached message whose `atMs` predates it. The specified glasses check rejects that message. **Fix:** create a fresh send-time envelope on reconnect while preserving `sinceMs`; test reconnect between heartbeat emissions. Also reject older messages within an established session.

- **Important — Task 9: sampler lifecycle and admission gates are missing.** The spec requires pipeline-enabled operation, but implementation gates only on the image switch. Direct `RoleRunner` calls also bypass existing thermal/battery admission, and nulling the sampler does not cancel an in-flight job. **Fix:** specify shared power/pipeline gates, cancellation, completion rechecks and single-flight protection across replacement instances. Test pause, severe heat and off→on during a call.

- **Important — Task 5: Bluetooth connection aggregation loses profile identity.** A device connected through both A2DP and HEADSET disappears when either profile disconnects. Changing “My car” while connected also leaves its classification stale. **Fix:** track `(address, profile)` connections and recompute aggregate kinds when either connections or selections change. Add both counterexamples to tests; specify receiver export flags appropriate for Bluetooth broadcasts. [Android broadcast guidance](https://developer.android.com/develop/background-work/background-tasks/broadcasts)

- **Important — Tasks 1, 10: watch delivery cannot reliably recover.** A LiveFit restart can reset `seq`, causing permanent rejection until receiver reset. A change rejected by the one-second limit may never be resent. Changes-only delivery also expires an unchanged activity after 30 minutes. **Fix:** define durable sequence/epoch behavior, retry or latest-state coalescing, and a periodic refresh contract. Test sender restart, rate rejection and a long unchanged activity.

- **Important — Task 8: the exact seed cannot be saved in the prompt editor.** `TemplateVariables.required()` requires `{{recent_context}}` for this new key, but the mandated seed omits it. `PromptEditor` also offers photo input only for `VISION_EXTRACT`. **Fix:** explicitly define intent template requirements and photo test-bed input; test saving and running the seeded prompt through the real editor path.

- **Important — Tasks 8, 12: encrypted upgrade verification is incomplete.** `SqlCipherMigrationDeviceTest` hardcodes version 4 and constructs older shapes by removing only wave-2 columns. After v5, those fixtures retain intent columns and can encounter duplicate-column migrations. JVM migration tests do not cover native SQLCipher. **Fix:** update those fixtures/assertions, add genuine encrypted v4→v5 coverage through both production builders, and run it against a disposable database before installing over user data.

- **Minor — Tasks 2–4: fusion rules contain unresolved cases.** The source table includes ON_BICYCLE as speed suspicion, but Task 2 does not. Watch-ASLEEP REST can yield confidence −1 from an absent glasses fraction. The fast-speed test expects 30 seconds despite the minimum 60-second exit from WALKING. **Fix:** resolve these contracts explicitly and add corresponding tests; anchor vehicle hold to the last raw vehicle evidence, never the held result.

- **Minor — Tasks 6, 12: diagnostics cannot support the stated checklist.** Stats ports do not specify how raw fix counts, location-on duration or battery readings reach the hub; the exact log line contains no reasons, although device steps require them. **Fix:** define the adapter snapshot/battery inputs and add enum-only reasons to diagnostics or revise the checklist.

- **Minor — Task 8 / final integration: migration ownership needs a merge gate.** Reserve v5 for Wave B; canvas slice 2 must regenerate its migration/schema after v5, normally as v6. **Fix:** explicitly verify the merged migration chain and schema identities before installation, including data-preserving upgrades from v3, v4 and v5.
