- **Critical — Tasks 5–6:** `retryable == true` includes `INVALID_OUTPUT` from `RoleRunner` and `NOT_SET` from `ModelRouter`. Both would bypass fallback and auto-rollback, potentially leaving photos permanently unprocessed. The proposed NETWORK/TIMEOUT/RATE_LIMIT/BUDGET enum values also do not exist. **Fix:** define propagation using actual failure kinds and causes; fall back for interpreter configuration/output failures; always rethrow cancellation. Test real `INVALID_OUTPUT` and `NOT_SET` exceptions with `retryable = true`.

- **Critical — Tasks 4–7:** Deleting existing traces does not fence in-flight writers. Live extraction, shadow jobs and experiment runs can reinsert forgotten data after Forget/Delete all; the intent sink runs before the claim/save transaction succeeds. **Fix:** carry the generation captured before photo loading, check generation and tombstones inside each output-write transaction, and commit intent metadata only for accepted extraction results. Add paused-model tests that forget/wipe before releasing the reply.

- **Critical — Tasks 4–5, 13:** Deletion by the row’s `frameId` misses shared outputs. `VisionExtractExecutor` copies a fact citing A+B into both frames’ rows; forgetting A leaves A-derived text in B’s row. Cluster summaries introduce the same problem. **Fix:** record every output’s input dependencies and delete all affected outputs, conservatively clearing the whole batch/cluster where necessary. Test forgetting one member of a multi-photo extraction.

- **Important — Tasks 4, 14:** Temporary slice-2 v4 conflicts with wave-2 v4. Later renumbering cannot repair a database already opened with that incompatible schema; checking only installed version numbers is insufficient. The handoff’s merge order also places slice 2 before wave B despite expecting v6. **Fix:** establish one canonical v3→v4→v5→v6 lineage, prohibit installing provisional schemas, and test upgrades from each canonical exported schema.

- **Important — Task 2:** Prompt CAS and the publish journal remain separate transactions. A crash or `insertPublish` failure can change prompts without a rollback record. Existing snapshots store fingerprints, so “expected = published text” also needs a legacy-record strategy. **Fix:** transact prompt writes and publish/rollback metadata together; derive published snapshots from the accepted drafts rather than rereading mutable active prompts. Check legacy fingerprints inside that transaction. Test failures between writes.

- **Important — Tasks 3, 5:** “Exactly one extraction per path” does not guarantee exactly one extraction per photo. Parallel edges to two extractors satisfy that rule while duplicating extraction. Ignoring an unwired `other` branch also accepts pipelines that necessarily fall back for those photos. **Fix:** validate runtime routing exclusivity and require coverage of every possible branch, including `other`. Add parallel-extractor and missing-default fixtures.

- **Important — Task 6:** Trace insertion, pruning, version loading and rollback bookkeeping are inside the extraction path without a clear failure boundary. A debug-table failure can discard successful extraction or prevent fallback. Step 5 also places rollback checking after “return.” **Fix:** separate extraction from best-effort telemetry, execute rollback evaluation before returning, and guarantee one returned extraction despite telemetry failures. Inject DAO failures in tests.

- **Important — Tasks 5–6:** Three prompt nodes can mean nine sequential calls for three photos, before extraction retries and fallback. This can exceed the existing 10-minute wake lock and 15-minute claim timeout. **Fix:** specify an elapsed-time limit with time reserved for fallback, or redesign claim renewal and wake-lock handling. Test budget waits and slow providers across the claim deadline.

- **Important — Tasks 7, 9:** A/B lacks a group lifecycle contract. Existing cancellation recognizes only the currently active run; cancellation between A finishing and B starting can miss both. `startAb` returns only a group ID while the API requires `runA`. **Fix:** reserve both run IDs, own cancellation and runner exclusion at group level, and return a typed result containing the IDs. Test cancellation at the A→B boundary and process recovery.

- **Important — Tasks 7, 9:** Shared `CallMeta` is copied onto every photo in an extraction batch. Summing item tokens would multiply usage; meanwhile `calls = 1` omits internal retries and single-photo fallback calls. **Fix:** record usage once per actual provider attempt and aggregate by call identity. Test a three-photo batch, rejected-output retry and single-photo fallback.

- **Important — Tasks 3, 12:** `callFactor` ignores extractor batch size and routing distribution. A single batch-1 extractor is reported as 1× although three photos require three calls; intent routing can require 4–6 calls rather than a fixed four. **Fix:** calculate a documented range respecting batch sizes and branch fan-out. Test homogeneous and mixed-label batches.

- **Important — Task 8:** Filtering `retrieve()` results by timestamp occurs after `MemoryRetriever` has already limited candidates and top-k. Newer memories can crowd out every historical hit; the newest-30 fallback has the same problem. **Fix:** apply `notAfterMs` before lexical/semantic candidate limits and fallback limits. Test many newer matches hiding an older relevant memory.

- **Important — Task 8:** Replay checks redaction only at entry. Forget/Delete all during the model call can still return forgotten text, unlike `AnswerService.answerOrThrow`, which fences the result. **Fix:** capture generation and retrieved IDs, then recheck ask redaction, generation and source liveness before returning. Test redaction and wipe during replay.

- **Important — Tasks 10, 14:** A SHA-256-only AndroidKeyStore key can fail TLS signing; Android documents that TLS keys commonly need `DIGEST_NONE`. A PKCS12 fixture cannot expose this. **Fix:** authorize the required signing digests and add real AndroidKeyStore handshake tests for TLS 1.2/1.3. Give the fixture loopback SANs so OkHttp hostname verification succeeds. [Android signing requirements](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder#setDigests(java.lang.String...))

- **Important — Task 10:** `CanvasWebRoute` currently initializes its URL once. LAN changes, port changes and certificate rotation need an explicit reload/token lifecycle. The Boolean `SslDecision` test exercises no certificate handling, and WebView may retain SSL decisions. **Fix:** rebuild/reload on origin or identity changes, clear retained SSL decisions, and test the actual callback with matching and mismatching certificates. [WebView SSL behavior](https://developer.android.com/reference/android/webkit/WebViewClient#onReceivedSslError(android.webkit.WebView,%20android.webkit.SslErrorHandler,%20android.net.http.SslError))

- **Important — Task 11:** Debouncing does not prevent older validation responses overwriting newer layouts. “Save before Freeze” also permits edits during the save to be omitted from the frozen version. **Fix:** reject stale validation responses using a draft revision; freeze an expected revision/hash or lock editing through save-and-freeze. Test reversed response order and editing during save.

- **Important — Tasks 1, 12:** Parsing assets and rendering exported views with canned JSON still never execute `app.js` startup, imports or route dispatch. Broken imports or an unreachable diff/Ask route can pass every named test. **Fix:** boot the actual application with browser globals and fake fetch, then navigate through every new route.

- **Important — Task 13:** Only `scene.group` receives whole-node chunking. `ai.cluster_summary` otherwise inherits `chunkSize = 1`, preventing grouping and multi-cluster packing. Its claimed maximum also ignores cluster fallback retries. **Fix:** make summary batching explicit, reuse `ClusterContract.call`, and derive safe call bounds. Test packing through `CanvasRunner`, rather than calling the executor directly.

- **Important — Task 14:** Memory Export is not a recoverable upgrade backup: `MemoryExport` omits photos and most database state. Instrumentation also starts the target application, whose startup opens the production memory graph. **Fix:** require a consistent database/photo backup preserving the existing Keystore installation, and run migration validation on isolated fixtures/copies before upgrading the production package.

- **Minor — Tasks 5–6:** The interpreter must merge extraction provenance, but `CanvasValue.Extraction` and `NodeResult` discard `ExtractedBatch.output.provenance`. **Fix:** carry it explicitly through executor results and test legacy-schema extraction against the direct path.

- **Minor — Tasks 9, 14:** The end-to-end test expects no active interpreter after rolling back Live, although the earlier Shadow publish becomes active again. The checklist also requests rollback history/reasons from an API specified to return only active rows. **Fix:** expect Shadow after the first rollback, and define a history response containing rollback timestamps and reasons.

- **Minor — Tasks 4, 6:** Seven-day retention runs only from interpreter activity. Traces can survive indefinitely after rollback or disabling shadow execution. **Fix:** prune through independent maintenance or on subsequent canvas access; test expiry with no active interpreter.
